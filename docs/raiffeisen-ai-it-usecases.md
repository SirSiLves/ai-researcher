# Raiffeisen Switzerland — AI for IT Itself
### One agentic-engineering foundation, five IT workloads that ride on it. For the Board.

> **One-line thesis.** "The harness is the moat, not the model" — frontier models are a *revocable commodity* (the June-2026 Fable-5/Mythos-5 takedown darked them worldwide in ~90 minutes); what is durable, owned, and defensible is the *way we build agents*. So the foundation bet is **UC-IT-0, the Genossenschaftswerkbank** — the cooperative agent-workbench: the single, sovereign-hosted, FINMA-by-default way an engineer at any of the ~200 banks authors a governed agent in hours instead of months. The two pre-existing substrates — a Swiss-resident, FINMA-08/2024-mapped agent *runtime* (**Agent OS**, the control plane) and a model that comprehends our Avaloq PL/SQL estate (**Avaloq Comprehension**) — are funded by the business-side portfolio. On top of all three, this brief rides **five IT workloads** that make IT itself cheaper and more resilient: see the whole cloud bill, forecast the nightly close before it breaks, make access-recertification real, map the un-inventoried batch periphery before we consolidate, and give a thin on-call bench institutional memory. **The five are zero/low-member-data on day one, none acts without a human, and each carries a board KPI we can back-test on our own data inside ~12 months — and each is authored FROM the workbench instead of hand-rolling its own harness, skills, MCP wiring, and eval.**

---

## 1. Bottom line

This is not a "should IT use AI" question — our ~4,000-seat multilingual Copilot already answers that. It is **"what is the foundation every agent is built on, and which IT workloads ride it first."**

The discipline that makes all of this fundable is **build the engineering base once, author every agent on it.** The five workloads each looked, at first, like a thin head on top of Agent OS. The deeper miss — flagged on review — is that *every one of them (and the business-side agents) silently re-invents its own harness, skills, MCP wiring, identity, and eval*. That fragmentation is exactly the trap the field warns against ("the infra around the agent mattered more than the model"). **UC-IT-0 is the answer: the build/developer plane (the Genossenschaftswerkbank) that complements Agent OS's run/control plane** — golden-path scaffold, a certified reusable Skill corpus (the open `SKILL.md` standard already proven in-house), blessed harness templates, an eval merge-gate, per-agent identity registration, and a secure agent SDLC, all sovereign-hosted and FINMA-mapped. An agent born from the workbench is inventoried, eval-gated, identity-scoped, and dossier-documented *by construction* — making six of FINMA 08/2024's eight control areas a default property, not a per-project scramble.

**Start with UC-IT-0 (minimum-viable-base) + Kassensturz (FinOps) + Beistand (SRE memory), in one 90-day Phase 0.** The base v1 is *not* the multi-year 8-layer platform — it is a scaffold + ~6 certified Skills + an eval-gate adapter + a handful of registry entries that a 6-8 FTE squad ships alongside the Agent OS Phase-0, and **Kassensturz and Beistand are its first two proof workloads — authored from the scaffold, not hand-rolled.** The other three (Pegel capacity-forecasting, SoD-Wächter access-evidence, Migra-Scout migration-discovery) follow and *pull* the deferred base layers (MCP signing factory, SPIFFE federation, typed memory) exactly as they need them.

Two framing decisions carried throughout, from the business-side discipline and the works-council sensitivity: **every CHF figure is capacity reallocated, not headcount cut** and is a placeholder until our own back-test replaces it; and **the base, because it propagates to all 200 banks by construction, is itself a critical model-risk asset** — it gets its own FINMA dossier and a canary/staggered/pull-based rollout, never a fleet-wide auto-push (see UC-IT-0 risk #1).

## 2. Why now — the IT-specific landscape

The general "why now" (FINMA is supervising AI and *enabling* not blocking; ~50% of Swiss institutions already use AI per FINMA's Apr-2025 survey; the ~9× open-weight cost gap; frontier access is revocable after the June-2026 Fable-5/Mythos-5 90-minute takedown) is in the business-side brief. The IT-specific reads that shape *these five*:

- **The agent control plane is now governable, off-the-shelf, and IT-shaped.** ServiceNow's **AI Control Tower** (Knowledge 2026) now spans discover/govern/secure/observe/measure across any system, ships a dedicated **AIOps specialist** (anomaly detection, event correlation, incident response), and absorbed **Veza** (access governance) + Armis + Traceloop. Its quoted ~99.2% noise-reduction / ~50% MTTR / ~70% outage-reduction numbers are **unaudited vendor figures** — but the *shape* is the signal: IT-ops, AIOps, SRE, asset-lifecycle and access are now first-class agent verticals, and the discipline has consolidated on **governable orchestration** (deterministic scripting layer matters as much as the model). Our equivalent of that control plane is **Agent OS** — we consume the commoditising plane and build only the cooperative-federation/dossier layer no vendor ships.
- **FinOps went agentic, and "AI-spend governance" is now mainstream.** The FinOps Foundation's *State of FinOps 2026* names AI-spend governance as a mainstream need; Flexera acquired **ProsperOps + Chaos Genius** to ship autonomous cost optimisation (up to 30% savings — *unaudited*). The pattern is real; the lesson for a cooperative is that the bottleneck is *ownership*, not detection — which is exactly what **Kassensturz** is scoped around.
- **Data-quality observability is a product category, and it maps 1:1 to a FINMA control area.** Monte Carlo (broad observability + field-level lineage + an agentic-observability layer), Anomalo (AI anomaly detection, minimal rules), Soda, dbt-tests. FINMA 08/2024 names **data quality** as one of its eight control areas — so a data-lineage/quality agent is a use-case whose value *is* a regulatory control. (We fold this into the honorable-mention **Linea**, see §8.)
- **Retrieval is reorganising around the agent loop.** Claude Code dropped vector search for grep; context-engineering is displacing one-shot top-k RAG, though enterprises still defend hybrid BM25+dense at volume. **Beistand** is built on exactly this — grep/structured retrieval with hybrid fallback — which is *why* it survives a frontier takedown.
- **In-network IT-AI precedent exists.** RBI-Austria scaled an internal Azure-OpenAI assistant past 20,000 staff (*unaudited*); SBB went live with a 30,000-employee multilingual RAG on Mistral; Crédit Mutuel reports ~1M advisor-hours freed (*unaudited*). The IT-side version of that is the ~4,000-seat Copilot we already run — **Beistand ships as a Skill on it**, not a new endpoint.
- **The build/developer plane is now a named category — and that's the foundation (UC-IT-0).** "Internal developer platform for agents" matured in 2026: **golden paths** scaffold a compliant new service/agent in minutes (CI, security policy, observability, catalog entry pre-wired); **Port's Apr-2026 Skills** auto-distribute catalog-defined skills to any MCP-compatible client with role-based permissions; the **`SKILL.md` standard is cross-tool** (32+ tools read the same file by March 2026 — Claude Code, Gemini CLI, Junie, Kiro, Goose, Codex, Cursor); and agent **identity has shipped standards** — the **NIST NCCoE concept paper (Feb 2026)** recommends **SPIFFE + OAuth**, and the **AIMS** stack (AWS/Zscaler/Ping/Defakto, Mar-2026) maps SPIFFE/WIMSE/OAuth onto a 9-layer agent identity model; Microsoft shipped **Entra Agent ID**; **OWASP Top-10 for Agentic Applications (2026)** is the threat baseline. The corpus through-line is blunt: *"the harness is the moat, not the model"* (Anthropic planner/generator/evaluator; Meta-Harness; OpenAI's "the infra around the agent mattered more than the model"; Hamel Husain's "package evals as reusable Skills"). **This is why the foundation counts more than any single app** — and why this repo's own `pipeline/skills/*/SKILL.md` files (16 of them, plain-YAML, authored by a small team) are the in-house proof the format works.

**Two guardrails we re-state because they bite hardest on IT use-cases:** (1) **"In-region Azure" (Zurich/Geneva) is NOT Cloud-Act-out-of-scope** — Microsoft is US-incorporated; only the **Swisscom Swiss AI Platform / Exoscale CH (Apertus/Mistral)** track is genuinely sovereign. Several of these use-cases pull from Azure Cost/management APIs, which are themselves a Cloud-Act surface. (2) **Frontier access is revocable** — anything load-bearing hedges to a **non-US frontier-grade model (Mistral Large) on the CH track**, *not* to Apertus-70B for hard reasoning. Apertus-70B is now available as a managed Swisscom endpoint (Apache-2.0, 8B+70B), but it is still **~12-18 months behind on code/comprehension** — benchmark it, use it for bulk non-sensitive work, do not pin a hard-reasoning workload to it.

## 3. The foundation + the five IT workloads

> Scoring note: the five workloads scored 8.0–8.25 on the 4-lens panel after the refute-by-default skeptic forced a re-scope. The "verdict" line under each is the skeptic's refuted-then-salvaged finding, kept visible on purpose — every headline below is the *salvaged*, back-testable claim, not the original over-reach. **UC-IT-0 below is the foundation the five ride on, scoped by the same adversarial process to a minimum-viable-base.**

### UC-IT-0 (THE FOUNDATION) — Genossenschaftswerkbank: the cooperative agent-workbench (build/developer plane)
**Effort M (v1 minimum-viable-base; full 8-layer platform is a deferred XL) · ~90 days, co-timed with Agent OS Phase-0 · zero member data**

- **Why it's the foundation, not a peer app.** Every other use-case answers "*what* agent do we run?" UC-IT-0 answers the prior, un-costed question: "*how* does an engineer at any of the ~200 banks author a governed agent fast, consistently, and survivably?" It counts more than any single app for three Raiffeisen-specific reasons: **(1) thin bench** — a cooperative with a small frontier-AI bench cannot afford five IT teams plus the business-side ones each hand-rolling harness, MCP wiring, identity, and eval; the base encodes scarce senior judgement *once* and inherits it everywhere. **(2) FINMA-by-default** — an agent born from the scaffold is inventoried, eval-gated, identity-scoped and engineering-evidence-documented *by construction*, making six of the eight 08/2024 areas (inventory, testing, documentation, monitoring, independent verification, governance) a default property. **(3) Harm floor** — a single-agent-default doctrine with a non-delegable human gate baked into every acting template is the only way "the agent never acts alone" becomes structural across 200 banks (WorkBench-Revisited: Opus 4.8 ~89% completion / ~2.5% harmful; 41-87% of multi-agent failures are coordination defects). It is the build face of objects whose run face already lives in Agent OS — the cut is **AUTHOR-vs-RUN**.
- **What it includes (v1 = minimum-viable-base, four layers only).** (1) **One golden-path scaffold command** (`raiffeisen agent new`, Backstage Software Template pattern, portable YAML) emitting a compliant skeleton: repo layout, pre-filled `AGENTS.md`, the **read-only planner/retriever/generator/evaluator harness template** (the "never-acts" shape both start-here agents need), a **SPIFFE workload-*registration* entry** (`spiffe://raiffeisen/<bank>/<agent>` — it *requests a binding from the Agent-OS SPIRE issuer*, it does **not** mint a credential), a stub per-agent engineering-evidence dossier wired to the Agent-OS 08/2024 template, an MCP manifest, and a CI pipeline gated on eval + zero-static-secrets + harm-floor/human-gate-present. (2) **~6 certified Skills** the two proof workloads actually consume — eval-as-a-Skill kit (deterministic-first AST/golden-file/Oracle-snapshot, escalating to a pinned calibrated LLM-judge), FINMA-engineering-evidence-builder, BA-Art.47/FADP tokenisation + PII-scrub-before-reasoning, indirect-injection/Plant-Persist-Trigger defense, CH-de/fr/it+Swiss-German localization, Skill-Card signer — each carrying a machine-readable **Skill Card** (owner, deps, license, eval status, risk tier, acts-vs-reads flag, ed25519 signature) on the `SKILL.md` standard already live in this repo. (3) **The eval merge-gate adapter** that *calls* the Agent-OS eval engine (we ship the eval definition format + red-team packs + hold-out discipline; **we do not build a second eval runtime**). (4) **Thin registry entries** for the Kassensturz connectors (Azure Cost API, OpenShift metrics) + the Beistand retrieval source, registered against the single Agent-OS gateway. The base also gets **its own inventoried, risk-tiered, version-pinned 08/2024 dossier with an independent-verification line** — it is a critical shared model-risk asset.
- **What it explicitly excludes.** **Deferred** to later tranches pulled by SoD-Wächter/Migra-Scout/federation: the two *acting* harness templates (ship only the read-only one first); the full MCP certification + **signing factory** (Sigstore/Rekor, SBOM/CVE, description-hash certification over ~7,500 Avaloq endpoints); the **hierarchical SPIFFE multi-tenant trust domain** (only needed at 200-bank federation); the **typed memory schema** (both start-here agents are memory-OFF); the **Firecracker authoring sandbox**. **Stays in Agent OS, referenced never rebuilt:** policy-routing, in-perimeter inference, the compliance-API audit surface, the per-agent identity *issuer/revoker* (SPIRE), the runtime inventory, the eval *run* engine, the memory store. **Stays in ModelDoc** (third actor): per-*model* validation dossiers — the base emits only the per-*agent* engineering-evidence slice and hands off. The base ships **zero** second eval runtime / gateway / identity issuer.
- **Agentic design (how the base is built and used).** The certified Skill corpus *is* the in-house `SKILL.md` standard scaled to *central-certify / federated-consume*; harness templates are code-as-harness reference implementations benchmarked at the **model-harness *pair* level (Harness-Bench)** so a model can be swapped under a takedown and re-certified. An engineer: runs `raiffeisen agent new` → the scaffold registers the SPIFFE entry, writes `AGENTS.md` + dossier stub, wires CI → imports certified Skills (eval, tokenisation, injection-defense) rather than re-writing them → declares allowlisted, scoped MCP tools from the registry → on commit, CI runs the eval merge-gate adapter (**one eval definition, invoked twice: at merge by build, as continuous monitoring at runtime by Agent OS — no divergent stacks**), the zero-static-secrets gate, and the harm-floor check → build **produces and signs an attestation**; **Agent OS is required to refuse any agent lacking that attestation** (admission-by-attestation is a *requirement placed on Agent OS*, not a property the base delivers alone). Single-agent-default is encoded in the scaffold; multi-agent only behind a justification Skill with MAST-taxonomy coordination-defect evals (deferred until an acting/multi-agent use-case exists).
- **Architecture.** Cheap sovereign/open default (Apertus-70B managed Swisscom endpoint for *bulk* non-sensitive build work — benchmark first, ~12-18mo behind on code); **load-bearing build-plane reasoning hedges to Mistral Large on CH-GVA-2, never Apertus**, and a **CI takedown drill asserts the *full build plane* survives** (scaffold, certification CI, eval gate all run with the frontier track dark + Mistral substituted) **plus a gate that re-runs every certified Skill on the sovereign model** — the *corpus* survives a takedown, not just the harness. **Multi-vendor for models AND the base's own tooling**: Backstage = CNCF/portable YAML; registry = open `modelcontextprotocol/registry` schema under LF AAIF (not a vendor catalog); signing store + SPIFFE root self-host from OSS; templates target the **LF-AAIF interop surface (MCP + A2A; MCP 2026-07-28 RC)** and **inherit Agent OS's one chosen agent-framework** (Microsoft Agent Framework/Governance Toolkit) rather than adding a second, with a named runtime-framework fallback. **The Agent-OS seam (shared objects, never duplicated):** one physical registry (build writes/signs the description hash; Agent-OS gateway is the only live-vs-certified verifier, fail-closed); identity (build *names/registers*, SPIRE *issues/revokes*); one eval definition (authored in build, run by Agent OS); the inference gateway (Agent OS runs it, the base ships the template+drill that consume it); the dossier (build emits the per-agent slice, ModelDoc owns per-model validation, Agent OS is system-of-record). **Infra-sovereignty hard constraint:** registry, signing store, and identity root sit on **Swisscom/Exoscale CH-GVA-2 — never in-region Azure** (Cloud-Act-in-scope), because the certified-Skill corpus is sensitive cooperative IP. **Perimeter disclosure carried verbatim:** tool execution stays in self-hosted sandboxes but the *model reasoning call still leaves*; the base never implies "code never leaves." Zero-static-secrets CI gate enforces 100% OIDC token-exchange **for scaffold-born agents at author-time** (residual: confused-deputy/token-theft persist; it cannot retro-fix the legacy estate).
- **Board KPI.** **Scaffold-to-certified-agent cycle time** — wall-clock from `raiffeisen agent new` to an attestation Agent OS will admit, **back-tested on Kassensturz vs a hand-rolled control.** Target is "hours not months" but that is **UNAUDITED** (Salesforce-+79%-class) and the slide carries the *measured* number, not the aspiration. **Guardrails (paired, so velocity never buys risk):** zero scaffold-born agents shipping a static MCP secret; 100% of acting agents with a non-delegable human gate at merge; takedown-drill pass = 100%; propagation-test coverage = 100% of certify events before fleet availability.
- **CHF value (placeholder, build-once-avoidance, capacity reallocated).** Avoids each of the five IT teams (plus business-side) independently re-building harness, MCP wiring, per-agent identity, secrets hygiene, the eval suite, and the FINMA evidence dossier; the cooperative multiplier is that a hardened injection-defense Skill or a tightened dossier-builder, certified *once*, propagates to all ~200 banks at the speed of a (version-pinned, staggered, pull-based) signed registry update — **one consolidated FINMA evidence trail instead of 200 divergent ones.** Value is **bench-conservation**: scarce senior judgement encoded once and reused, freeing senior engineers toward higher-judgement work with an enforceable works-council redeployment commitment. **No CHF multiplier on the slide** — gated on the measured scaffold-to-ship cycle-time delta on Kassensturz vs a hand-rolled control. Security value rests on **risk-eliminated-before-ship** (eval-gate, injection-defense-by-default, zero-static-secrets-by-construction), never on the unverified "fixing is the new bottleneck" thesis.
- **Effort.** **M for the v1 minimum-viable-base** (scaffold + ~6 Skills + eval-gate adapter + thin registry entries + the base's own dossier), 6-8 FTE reusing the Agent OS squad inside Phase-0. The full 8-layer Genossenschaftswerkbank (signing factory, SPIFFE federation, typed memory, acting/deterministic templates, Firecracker sandbox) is the deferred XL — *a thin bench cannot ship the 8-layer platform, which is the whole point of scoping down.*
- **Top risks.** (1) **Correlated systemic risk (gravest — the base is *worse* on this axis than Agent OS).** A bug in the scaffold or a certified Skill propagates *by construction* to all ~200 banks at the speed of a signed update — the same propagation the leverage story sells is the concentration FINMA penalises under **Circ. 2023/1**. *Mitigation:* the base gets its **own dossier + independent-verification line**; federated consume is **version-pinned, staggered, pull-based** (canary cohort = central org + 3-5 pilot banks, soak window, banks pull on their own cadence — each remains an independent revocable controller); a **correlated-defect kill-switch** (fleet-wide revoke + each bank retains last-known-good, no monoculture); a **blast-radius propagation test** before any certify; the correlated-bug scenario is a *named, drilled* incident class. (2) **Vendor lock-in;** *mitigation:* every base-tooling choice passes a survives-substitution check (portable YAML, open registry schema, OSS self-host, SKILL.md is plain markdown, corpus re-run on the sovereign model). (3) **Thin-bench buildability;** *mitigation:* v1 is the MVB, deferring the heavy layers to later tranches; SKILL.md authoring is provably low-barrier (16 live files in-repo), certification stays central + CI-automated. (4) **Seam leakage (rebuilding Agent OS by accident);** *mitigation:* the three historically-blurry seams are closed — no eval runtime, register-don't-mint identity, ModelDoc as the third dossier actor; exactly one registry, one writer, one runtime verifier.
- **Verdict.** *Adversarial critique:* **FUND, but as the scoped v1 that rides Agent OS — not the 8-layer platform as written.** The thesis is correct and well-anchored, the AUTHOR-vs-RUN seam is the right cut, and it genuinely complements rather than re-pitches Agent OS — once the three seams are closed and the correlated-systemic-risk is dossiered + staggered. *"The highest-leverage compliance and bench-conservation asset in the portfolio."*

### The five workloads

### UC-IT-1 (START HERE) — Kassensturz: federated FinOps & OpenShift right-sizing
**Panel 8.0 · effort M · ~6-8 weeks to first agent-owned value · zero member data**

- **Problem.** Raiffeisen is ~200+ legally-independent banks plus the central org, so cloud + self-managed-OpenShift cost lands in split cost-centres and **no single CFO ever sees the consolidated platform bill** — waste accumulates precisely because each line is *unowned*. Off-the-shelf FinOps tools don't solve a cooperative's attribution gap.
- **What it does (v1, two measured tracks).** **Track A — Detection & Attribution (the v1 win, agent-owned, governance-free):** normalise Azure Cost Management exports + OpenShift requests-vs-usage / namespace-activity / PVC-binding telemetry into one *showback model keyed by accountable owner*; detect five waste classes (idle namespaces, over-requested pods, orphaned PVCs, unattached Azure disks/IPs, zombie dev/test envs) and file **owner-attributed tickets with evidence**. **Track B — CHF accounting, split into two labelled buckets:** (i) **spend-reduction** = consumption-billed Azure orphan reclaim — the *only* near-term CHF on the slide, back-tested on our own bill; (ii) **capacity-avoidance** = OpenShift right-sizing reported separately as deferred node purchase, never as a monthly-invoice drop.
- **What it explicitly excludes.** No autonomous destructive action — never deletes a PVC, kills an env, or de-provisions an Azure resource; it files tickets a named human approves. "CHF off the monthly platform invoice" is *demoted* from a v1 promise to a lagging secondary. Any cross-bank reclaim CHF is **deferred** until the cooperative ratifies a use-it-or-reclaim policy + funds a central platform-engineering allocation to execute tickets — named on the slide as a dependency the use-case does *not* own. No member data, no Avaloq core telemetry, dev/test before prod.
- **Agentic design.** Planner/generator/evaluator, hard human gate. Planner decomposes "find+attribute waste in tenancy X" into deterministic data-pulls. Generator drafts owner-attributed tickets (cheap open-weight on the sovereign track; **resource names tokenised before the model call**). Evaluator is the adversarial reviewer ("is this 'idle' namespace a quarterly batch job? is this 'orphaned' PVC a DR volume?") and is the engine behind the back-tested precision KPI. **Nothing in the loop acts** — the only actor is the named human owner. (Direct WorkBench-Revisited mitigation: at the scale of thousands of resources, the ~2.5% harmful-action floor means daily incidents without a hard gate.)
- **Architecture.** Cheap sovereign/open default (Apertus/Mistral on Swisscom/Exoscale CH-GVA-2) for high-volume drafting — comprehension-light, so safe to pin to the sovereign track; degrades gracefully under a frontier takedown. Reuses Agent OS federated multi-tenant connectors (Azure Cost API + OpenShift metrics); no Avaloq coupling. **Confidentiality-class, not secrecy-class:** namespace/PVC/resource names reveal *which regional bank runs what* (BA Art.47-adjacent) and the Azure Cost API is itself a Cloud-Act surface — tokenise before any cross-tenant aggregation. FINMA 08/2024 dossier (low risk-classification; data-quality on cost feeds; back-test = testing/monitoring; per-ticket evidence = explainability; evaluator + human gate = independent verification). OAuth/OIDC + per-agent identity from day one.
- **Board KPI.** **Showback coverage** — % of combined Azure+OpenShift spend now attributed to an accountable owner (target: from near-zero consolidated visibility to >85% in 9 months). **Guardrail:** detection precision on the labelled waste back-test ≥90% (a false "orphaned" call that triggers a wrongful reclaim is the trust-killer). Azure-only spend-reduction CHF rides as a labelled secondary.
- **CHF value (placeholder, capacity reallocated).** Track (i) spend-reduction: **~CHF 0.8-2.0M/yr**, *assuming* the in-region Azure tenancy size and validated only by our own Azure-bill back-test. Track (ii) capacity-avoidance: **~CHF 1.5-4M** of deferred future capacity, realised as reallocated platform budget in a named cycle, gated on the ratified policy. Vendor "30%-savings" figures are **unaudited** and excluded.
- **Top risks.** (1) **Action-rate / governance stall** (the skeptic's primary refutation) — the agent owns the numerator but nothing in `tickets × action_rate × per-ticket-saving`; *mitigation:* no reclaim-CHF target on the slide until the cooperative ratifies the policy. (2) **KPI-mechanics mismatch** — self-managed OpenShift right-sizing improves bin-packing but doesn't drop the invoice; *mitigation:* split the two CHF tracks, never report capacity-avoidance as an invoice line. (3) **False-positive reclaim** (a reclaimed DR volume → outage); *mitigation:* ≥90% precision guardrail, adversarial evaluator, dev/test first, agent never acts. (4) **Metadata confidentiality leak;** *mitigation:* tokenise resource names, keep reasoning on the sovereign track.
- **Verdict.** *Skeptic refuted* the "CHF off the monthly invoice" headline (the bottleneck is org/political reclaim consent, not waste-detection; OpenShift right-sizing can't drop a self-managed invoice). *Salvaged:* lead v1 with the governance-free **detection+attribution** KPI; the franc-savings is a labelled, policy-gated secondary. **This is the cleanest cooperative cost play and the safest place to prove Agent OS.**

### UC-IT-2 (START HERE) — Beistand: on-call SRE runbook copilot (drafts, never executes)
**Panel 8.0 · effort M · ~4-9 months · zero member data day-1 (PII-scrubbed)**

- **Problem.** A thin SRE bench: deep Avaloq/Exadata/OpenShift knowledge sits with a handful of seniors, runbooks are scattered/stale, a CH-de/fr/it + Swiss-German rota re-derives the same diagnosis each incident, and PIRs get skipped so institutional memory never compounds. The board itself names the thin-bench constraint.
- **What it does.** **v0 (0-4 mo):** seniors author a *frozen* curated corpus of the 15-25 highest-frequency operational incident classes (Avaloq ACP/AFP, Exadata, OpenShift, Java/Eclipse) into a structured template with a staleness flag. **v1 (4-9 mo):** a Skill on the live ~4,000-seat Copilot that, once an *operational* incident is declared, retrieves the matching runbook + N most-similar past incidents/PIRs, summarises prior diagnoses, drafts a candidate remediation in the on-caller's language, and after resolution drafts the PIR skeleton for human edit.
- **What it explicitly excludes.** **No execution, ever** — no step run, no script triggered, no config changed, no prod credentials held. ## 6. What we are NOT doing / traps

- **NOT letting any of these ACT.** All five draft, rank, forecast, or map — *a named human is the sole actor* on anything that changes state (reclaim a resource, run a runbook step, retune a batch, revoke an entitlement, disable a job). This is the direct mitigation for the WorkBench-Revisited ~2.5% harmful-action floor: at IT scale, an acting agent means daily incidents without a hard gate.
- **NOT claiming "code/data never leaves the perimeter."** Tool execution stays in self-hosted sandboxes; the *model reasoning call still leaves*. We say "member data never *enters*" (and engineer the tokenisation/PII-scrub that makes it true), not "nothing leaves."
- **NOT conflating "in-region Azure" with sovereign.** Microsoft is US-incorporated; the Azure Cost/management APIs several of these pull from are a Cloud-Act surface. The genuinely sovereign track is Swisscom/Exoscale + Apertus/Mistral on CH-GVA-2.
- **NOT pinning load-bearing reasoning to Apertus.** Apertus-70B is now a managed Swisscom endpoint and is the right *bulk/non-sensitive* lever and the right *sovereignty* hedge — but it's ~12-18 months behind on code/comprehension. The hard-reasoning fallback (SoD-Wächter, Migra-Scout planner, Beistand hard tier) is **Mistral Large on CH**. Benchmark Apertus before trusting it with anything reasoning-hard.
- **NOT running production MCP on long-lived static secrets.** ~53% of production MCP servers do (only ~8.5% OAuth) — a FINMA-audit failure. OAuth/OIDC + per-agent cryptographic identity from day one.
- **NOT building a value case on "fixing is the new bottleneck."** Only the *detect/discovery* side is independently verified (CVE/NIST/FIRST, Glasswing). Migra-Scout's value is confined to discovery FTE-weeks; SoD-Wächter to seeded-pair recall; neither asserts a remediation-throughput thesis. **All cross-bank ROI numbers are unaudited and excluded from the slide.**
- **NOT promising what we can't back-test.** Beistand drops the MTTR-cut headline (no permissible counterfactual on a live regulated incident stream); Pegel keeps "breaches avoided" observational-only; Kassensturz demotes "CHF off the invoice" to a policy-gated secondary; SoD-Wächter drops "fewer audit findings." Each board headline is a clock or recall figure the copilot owns and we can ground-truth on our own data.
- **NOT stacking one angle.** We deliberately picked one each of FinOps / capacity / access-evidence / migration-discovery / SRE-memory, dropping the three-deep cost cluster (Tokenwacht, Lizenz-Lotse) and the DevSecOps-discovery trio (Aegis-Discover, Genoss-SBOM, Keyring) to keep the portfolio diverse — see §8.
- **NOT building the base as the 8-layer platform up front, and NOT auto-pushing it to 200 banks.** UC-IT-0 v1 is the minimum-viable-base two read-only agents need; the signing factory, SPIFFE federation, and typed memory are *demand-pulled* later. And because a shared base propagates by construction, a bad certified Skill is a *correlated systemic risk* (FINMA Circ. 2023/1 concentration lens) — so the base carries its **own dossier + independent verification**, rolls out **canary→staggered→pull-based with last-known-good fallback** (no monoculture), and treats the correlated-bug scenario as a named, drilled incident class. The propagation that gives the cooperative its leverage is the same thing FINMA penalises; we mitigate it explicitly rather than sell it.
- **NOT re-building Agent OS inside the base (the AUTHOR-vs-RUN seam).** The base does not run a second eval engine (it ships the eval *definition* + adapter), does not *mint* identities (it *registers* a SPIFFE entry against the Agent-OS SPIRE issuer), and does not own the dossier-of-record (it emits the per-*agent* engineering-evidence slice; ModelDoc owns per-*model* validation; Agent OS is system-of-record). One physical registry, one writer (build), one runtime verifier (control).

**The decision the board must make:** approve a **foundation-plus-two-workloads Phase 0** — fund the **minimum-viable agentic-engineering base (UC-IT-0)** and prove it on the two start-here workloads (Kassensturz + Beistand), rather than greenlighting parallel IT pilots that each re-solve harness, skills, identity, and eval. The base is the bet that "the harness is the moat"; the two workloads are how it earns its first board-legible number.

**First funding ask (90-day Phase 0, ring-fenced) — one 6-8 FTE central squad, reusing the Agent OS squad:**
1. Stand up the **minimum-viable-base**: the `raiffeisen agent new` golden-path scaffold (read-only harness template, register-don't-mint SPIFFE/OIDC identity, stub 08/2024 dossier, CI gates), ~6 certified Skills (eval kit, FINMA-evidence-builder, tokenisation/PII-scrub, injection-defense, CH-de/fr/it localization, Skill-Card signer), the eval merge-gate adapter calling the Agent-OS engine, thin registry entries — **plus the base's own 08/2024 dossier with an independent-verification line.**
2. Author **Kassensturz Track-A from the scaffold** (Azure Cost + OpenShift connectors, five-class detector, evaluator/back-test, confidentiality-tokenisation) → a **consolidated showback view + labelled-waste back-test** ("we now see the whole bill and who owns each line").
3. Author **Beistand v0 from the scaffold** as a Skill on the existing Copilot: seniors author the frozen 15-25 incident-class corpus; PII-scrub-before-reasoning path live.
4. Open the **FINMA AI Desk dialogue** (base-as-shared-model-risk-asset *and* the critical-process touches) and run a **full-build-plane takedown drill** confirming the scaffold/CI/eval-gate and every certified Skill run with the frontier track dark and Mistral Large on CH-GVA-2 substituted.

**Phase-0 exit criterion (Day 90):** (a) the MVB live, with two agents **authored from it, not hand-rolled**, and the **back-test-gated scaffold-to-certified-agent cycle-time** number (vs a hand-rolled control); (b) a consolidated Azure+OpenShift showback view with a ≥90%-precision labelled-waste back-test on Raiffeisen's own bill; (c) a frozen Beistand corpus with the PII-scrub path live; (d) a passed full-build-plane takedown drill; (e) the base's own dossier + the reusable per-agent engineering-evidence pattern the scaffold auto-emits — the evidence pack the board funds the NEXT window (Pegel, SoD-Wächter, which pull the deferred base layers) against, with **zero member data at risk.**

## 8. Method, the wider field, and honorable mentions

**Method (the five workloads).** A wide field of **24 IT candidates** was generated across six angle-bands (AIOps/SRE/observability; ITSM/access; FinOps/cloud; data-platform/data-quality + DevSecOps-discovery; release/IaC/migration; plus a live-web-research scout), merged to a **16-candidate field**, and scored by a **4-lens adversarial panel** (FINMA/model-risk, CIO/budget-ROI, tech-durability, executable) with penalties for undefendable-to-FINMA / single-vendor lock-in / no-measurable-12-month-value / member-data-day-1 / duplicates-existing / value-rests-on-fix-bottleneck. A **refute-by-default skeptic** then attacked each candidate's single riskiest claim — *every* headline was refuted and the survivors re-scoped around what is back-testable (those salvage fixes are the §3 verdict lines). A completeness critic audited the final set for coverage, duplication, evidence-integrity, member-data posture, and sequencing.

**Method (UC-IT-0, the foundation — added after the five, on the user's "this counts way more" steer).** A dedicated research pass over **six base dimensions** (certified skills; harness templates + secure agent SDLC; internal MCP/tool registry; orchestration doctrine; security + identity; eval + memory + runtime), each combining the corpus with live web research, was synthesised into one base definition with an explicit **build-plane-vs-Agent-OS-control-plane seam**, then **adversarially critiqued** on five fronts (Agent-OS duplication; FINMA correlated-systemic-risk for a shared base; sovereignty/lock-in; over-claim; thin-bench buildability) which forced the scope-down to a **minimum-viable-base** and closed three leaking seams (eval runtime, identity minting, the ModelDoc third actor). Grounding incl. the cross-tool `SKILL.md` standard, NIST-NCCoE AI-agent identity + AIMS (SPIFFE/OAuth), Backstage golden paths, Port/AWS-AgentCore/JFrog skill registries, OWASP Agentic Top-10, MCP 2026-07-28 RC + LF AAIF.
