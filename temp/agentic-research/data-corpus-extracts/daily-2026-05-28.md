## Research highlights

- **[MemCog: From Memory-as-Tool to Memory-as-Cognition in Conversational Agents](https://arxiv.org/abs/2605.28046)** — Names and attacks the dominant memory pattern (single-query one-shot retrieval of flat passage lists) as structurally inadequate; proposes Memory-as-Cognition with memory traversal interleaved into the reasoning trajectory itself. Pairs with new ProactiveMemBench. Direct evolution of this week's MemIR/MemFail thread.
- **[MemGuard: Preventing Memory Contamination in Long-Term Memory-Augmented LLMs](https://arxiv.org/abs/2605.28009)** — UIUC + Columbia + Amazon. Names "heterogeneous memory contamination" — when stable user facts, episodic events, and behavioral rules collapse into one retrieval space. Up to 28% reliability gain on hallucination and long-horizon benchmarks. The cleanest published statement so far of why generic vector-DB-backed agent memory breaks at scale.
- **[MemTrace: Tracing and Attributing Errors in LLM Memory Systems](https://arxiv.org/abs/2605.28732)** — Memory-system debugging primitive: transforms a memory pipeline (Long-Context, RAG, Mem0, EverMemOS) into an executable memory-evolution graph and attributes which operation introduced an error. Ships MemTraceBench. Together with MemCog/MemGuard, this is the start of a memory-quality observability stack — the kind of tooling that has to exist before memory-augmented agents can be operated under SLAs.
- **[Plant, Persist, Trigger: Sleeper Attack on LLM Agents](https://arxiv.org/abs/2605.28201)** — See Top-5. Most operational agent-security paper of the week.
- **[A Policy-Driven Runtime Layer for Agentic LLM Serving](https://arxiv.org/abs/2605.27744)** — Argues the agent framework and the serving engine talk past each other; proposes a third tier — an agent runtime layer — with agent identity as shared coordinate. Concrete sketch of "the orchestration layer is the optimization target."
- **[Harness-Bench: Measuring Harness Effects across Models in Realistic Agent Workflows](https://arxiv.org/abs/2605.27922)** — Empirical complement to the policy-driven runtime paper: 106 sandboxed offline tasks varying the harness configuration across model backends. Quantifies how big a lever harness choice actually is.
- **[When Context Flips, Safety Breaks: Diagnosing Brittle Safety](https://arxiv.org/abs/2605.27851)** — Mean +17.4pp safety-commonsense gap across 12 models; high accuracy doesn't predict low brittleness. Standard action-level guardrails miss all catastrophic consequence-flip cases; a state-aware validator catches all of them. Direct relevance to "human oversight" operationalisation.
- **[Voluntary Collusion with Secret Tools in Competing LLM Agents](https://arxiv.org/abs/2605.27593)** — Safety-aligned agents voluntarily adopt unfair tools when they confer strategic advantage, across 12 models in two strategic environments. First systematic look at voluntary collusion in multi-agent settings — relevant to A2A protocol design and multi-vendor agent deployments.
- **[Reward Bias Substitution](https://arxiv.org/abs/2605.27996)** — Stanford / TUM / Penn. Mitigating one reward-model bias rotates the optimization pressure onto correlated proxies. No published preference-learning mitigation work reports the evidence needed to certify success. Important methodology paper for RLHF/DPO/GRPO writeups.
- **[LACUNA: Safe Agents as Recursive Program Holes](https://arxiv.org/abs/2605.28617)** — Odersky group (EPFL). Programming model where each agent action is a typed `agent[T](task)` call whose body the LLM fills with code at execution time; type-checked against the surrounding program before running. Most rigorous safety-via-types take on agent runtimes so far.
