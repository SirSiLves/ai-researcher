## Long-form picks

- **Evaluation Patterns for Deep Agents in Production** — LangChain (2026-07-08). _Takeaway:_ A hands-on engineering write-up from building and shipping four production "deep agents" (stateful, long-running agents for coding, email, and agent-building) — the interesting part is that traditional single-shot LLM evaluation broke down, so they codified five distinct patterns instead: bespoke per-datapoint assertions, single-step evals for individual decision points, full-agent-turn end-to-end tests, multi-turn conversations with conditional logic, and reproducible environment setup (API mocking, containerized state). Uses LangSmith's Pytest/Vitest integrations so every test emits a debuggable trace over trajectories, final responses, and state artifacts. A concrete eval/observability pattern reference rather than a product pitch, and a useful counterpoint to the "just use an LLM judge" default. [link](https://www.langchain.com/blog/evaluation-patterns-for-deep-agents-in-production)

- **Congress Should Do Something: The Case for (Fixing) the Great American AI Act** — Lawfare (2026-07-08). _Takeaway:_ Argues the Obernolte–Trahan discussion draft (GAAIA, released Jun 4) is the strongest federal frontier-AI safety framework proposed so far — but that its sweeping preemption of state AI laws makes it net-negative as written, because it would clear the existing state-level floor without putting an equivalently enforceable federal one in its place. A substantive, position-taking governance analysis of the concrete US legislative vehicle now in play, distinct from the export-controls / national-security / Pentagon-designation essays logged in prior daily files. [link](https://www.lawfaremedia.org/article/congress-should-do-something--the-case-for-(fixing)-the-great-american-ai-act)

- **How Kent Beck Shapes the Software Engineering Industry** — Gergely Orosz (The Pragmatic Engineer), with Kent Beck (2026-07-01). _Takeaway:_ Beck's central claim is that AI has "wiped the professional playbook clean," returning every engineer and company to an *explore* phase where the honest answer is "nobody knows" how to build software now — and that the real bottleneck was never the code but *trust* (that the program does what it should, among teammates, with users), which we are failing to accumulate at anywhere near the rate we now accumulate generated code. Includes a concrete agentic-coding practice: annotate tests as *immutable* so a coding agent can't take the path of least resistance and quietly weaken your logic when it hits a hard bug. A named-practitioner position on the agentic-coding debate, more on-slice than the broader "impact on software engineers" survey logged earlier. [link](https://newsletter.pragmaticengineer.com/p/how-kent-beck-shapes-the-software)

### mcp
- **[MCP Deep Dive, Part 3: Build a Production-Grade MCP Server From Scratch](https://medium.com/@randhir.jassal/mcp-deep-dive-part-3-build-a-production-grade-mcp-server-from-scratch-1debcc955888)** — Randhir Jassal (Jul 6, 2026). Actual from-scratch build (part 3 of a series) rather than a survey: takes one server end-to-end and focuses on the production concerns that separate a demo from a service — surviving an agent hammering it ~85k times/day across tenants without leaking stack traces, OOM-ing on a big query, or dropping calls on deploy. Distinct from the "MCP is a service you operate" and "MCP killed the session" pieces logged earlier.

### agentic-ai
- **[Loop Engineering: Why the Agent Era Needs a Runtime, Not a Longer Prompt](https://jinlow.medium.com/loop-engineering-why-the-agent-era-needs-a-runtime-not-a-longer-prompt-b5aa34944fb4)** — JIN (Jul 2026). Independent practitioner argument that agent reliability is fundamentally a runtime-and-control-loop problem, not a prompting or context-window-size problem — agents loop, call tools, use files, maintain memory, and hand work to sub-agents, so the unit of engineering has moved from the prompt to the loop/runtime. A first-principles position piece; complements (not a duplicate of) LangChain's vendor "Art of Loop Engineering" post logged 07-06.

### ai-engineering
- **[Chapter 8: Agent Evaluation for LLMs: How to Test Tools, Trajectories, and LLM-as-Judge](https://medium.com/@vinodkrane/chapter-8-agent-evaluation-for-llms-how-to-test-tools-trajectories-and-llm-as-judge-788f6f3e0d52)** — Vinod Rane (May 2026). Concrete agent-eval methodology, not a tool round-up: hand-crafted "goldens" (50–100 anchor cases) vs. production-trace mining (≥500 labeled cases before trusting aggregate metrics), uncertainty-aware judge outputs (confidence intervals / abstentions instead of a fake "3.7/5"), and evaluation-driven development (write eval cases with expected trajectories before writing agent code). Slightly older than the day's other picks but genuinely hands-on and unlogged.

### ai-governance
- **[AI for Whom? Labor Justice, Digital Inequality, and the Social Governance of Artificial Intelligence](https://medium.com/@tangyong065/ai-for-whom-8127a0672cc8)** — David (Jul 2026). Position-taking governance essay on the distributional dimension that US-policy pieces mostly skip: high AI-usage rates in lower-income economies don't translate into gains, because use is concentrated in free consumer tools while enterprise/research/industrial deployment stays locked out by infrastructure; and >90% of leading-LLM training data comes from a handful of languages, creating a real language divide (Swahili, Hausa, Bengali, Punjabi, etc.). Grounds the argument in a UNDP Dec-2025 report on AI widening between-nation inequality. A distinct global-equity angle from the day's US-legislative pick.
