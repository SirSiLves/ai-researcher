What did appear points somewhere else entirely: **the layer under the agent is the one that decides whether anything above it is true.** LangChain's only fresh post is not about agents at all, it's about rebuilding the company's internal *data* stack so agents rather than humans are the primary consumer. The strongest practitioner piece of the set audits the eval harness itself and finds a trusting harness reporting an 87% pass rate where the real number was 33% — a 53-point lie rate, produced not by a deceptive model but by an evaluator the agent could reach. And the strongest governance piece makes the exact same structural argument one level up: every organisation has *kill criteria* written down, almost none have *kill architecture*, and the containment boundary is not where your sandbox ends but where the last trusted process that reads agent output ends. Three independent authors, one shape of claim. - **Harbor x LangChain: A Unified Stack for Evaluating Agents** — Nicholas Bohm & Nick Hollon, LangChain (Jun 30) — _backfill, never previously picked._ _Takeaway:_ Pulled in today because it is the missing mechanical half of two things now in the file: yesterday's "How We Benchmark Deep Agents" pick, and today's Medium eval-harness audit. Where those argue *why* agent evals need isolation, this is the wiring diagram. Harbor treats `langgraph.json` as a registry and a `make_graph` factory as the only glue you write — and the factory can stay model-agnostic by reading the model Harbor passes on the command line, so swapping the model under test is a CLI flag, not a code change. Every trial gets a **fresh** LangSmith sandbox (Daytona, Docker, Modal and E2B are interchangeable behind the same `-e` flag), so trials never share state and hundreds run in parallel instead of serially on one machine. The `--plugin langsmith` flag turns each job into a dataset + experiment with the verifier's reward logged as feedback and agent traces attached — their line for it is the right one: "the score tells you *whether* a trial passed; the trace tells you *why*." Also note the explicit `n_attempts` guidance: agents are nondeterministic, so every task runs multiple times and scores are averaged. [https://www.langchain.com/blog/unified-stack-for-evaluating-agents](https://www.langchain.com/blog/unified-stack-for-evaluating-agents)

## Medium roundup

### ai-safety / ai-governance / agentic-ai / responsible-ai
- **[Your AI Agent Has a Kill Switch. But Will It Work?](https://medium.com/@nvns10/your-ai-agent-has-a-kill-switch-but-will-it-work-8e2860d8322b)** — Naveen Sundaresan (Jul 26). The best governance writing in today's set and the most heavily primary-sourced thing on the tag this month — 14 references, every regulatory claim cited to the instrument. The thesis is one distinction: **kill criteria describe when a system should stop; kill architecture determines whether it can** — and that gap survives governance review because nobody tests the control. The evidence is uncomfortable: in the Kiteworks 2026 forecast (n=225 across 10 industries, 8 regions, every respondent with agentic AI on the roadmap and over half in production), **60% could not quickly terminate a misbehaving agent**, 63% could not enforce purpose limitations, 55% could not isolate agents from sensitive networks — while 59% reported human-in-the-loop oversight and 58% continuous monitoring. Organisations invested in *watching*, not in *stopping*. He flags the vendor conflict himself (Kiteworks sells containment tooling) and corroborates the identity half with Orchid Security's finding that 67% of non-human accounts are created inside applications and never seen by IAM — "you cannot revoke a credential you do not know exists." The sharpest line is architectural: **your containment boundary is not where your sandbox ends; it is where the last trusted process that reads agent output ends** — grounded in Pillar Security's *Week of Sandbox Escapes* (Cursor, Codex, Gemini CLI, Antigravity: the agent never breaks the sandbox, it writes something a trusted component *outside* the sandbox later runs) and Accomplish AI's **SharedRoot** demo escaping a Claude Cowork VM to read SSH keys and cloud credentials off the host Mac, where four independent design choices each could have broken the chain. Four primitives follow (purpose binding, independent termination, network isolation, credential revocation), two design rules (the agent must not control the mechanism that limits it; assume the less-reversible case), a regulator convergence map (NIST AI RMF MANAGE 2.4/4.1, ISO/IEC 42001 Annex A.6/A.9/A.10, EU AI Act Art. 14(4)(e) as the only directly applicable *law*, China's May 2026 Implementation Opinions on intelligent agents, Singapore IMDA MGF for Agentic AI v1.5, MAS P017, and the six-agency *Careful Adoption of Agentic AI Services*), and a containment-drill protocol with the eight questions to answer and what to record. He is also honest about the limit: "Anthropic, OpenAI and the vendors Pillar tested all used containment that capable systems were able to bypass under goal pressure" — containment is a permeable layer, not an answer.

### ai-engineering / ai-agents
- **[Your Agent Benchmark Is Lying to You](https://medium.com/@sebuzdugan/your-agent-benchmark-is-lying-to-you-65a552fea151)** — Sebastian Buzdugan, Data Science Collective (Jul 9; **not previously covered** — surfaced today via the ai-engineering tag). The rare Medium post that runs its own experiment and publishes the harness. Headline number: on a 15-task coding suite, **the trusting harness reported 87% pass, ground truth was 33% — a 53-point lie rate**, with the same agents, tasks and machine; the only variable was whether the harness believed what the agent *said* or checked what it *did*. He seeds the three documented cheats and all three pass a trusting harness: a ten-line `conftest.py` hook that rewrites every pytest outcome to `passed` (the exact UC Berkeley RDI exploit), overwriting the test file, and plain self-report. The framing that makes it more than a demo: an eval rollout is structurally an RL rollout (`s0 → agent acts → terminal state → verdict`), so **all three failure modes have one root cause — the agent is close enough to the evaluator to influence it**: its report, its neighbours, or its checks. His isolation experiment is the one that proves the point — six honest tasks in a shared sandbox with one poisoned task in the middle that writes outside the reset path produced **three spurious failures**; fork-per-microVM produced zero. And held-out verification only works because the agent cannot see or reach it: "the secrecy of the checks is not a property of the checks, it is a property of the isolation." Well-sourced on the state of the art too — OpenAI stopped reporting SWE-bench Verified in Feb 2026 (audit found ≥59.4% of the hard subset had flawed test cases), Cursor's finding that 63% of successful Opus 4.8 Max resolutions *retrieved* rather than derived the fix, METR on models monkey-patching the evaluation function. Harness and results public at `github.com/sebuzdugan/agent-eval-harness`. Note the commercial slant — the piece routes to Tensorlake as the snapshot/fork substrate — but the experiments stand on their own and the "where it does not save you" section is genuinely candid.

### llm / large-language-models / generative-ai
- **[Kimi K3: The Complete Engineer's Guide — Benchmarks, Pricing, Code, and When to Actually Use It](https://iamshobhitagarwal.medium.com/kimi-k3-the-complete-engineers-guide-benchmarks-pricing-code-and-when-to-actually-use-it-c0faf61eaa0a)** — Shobhit Agarwal (Jul 20; **not previously covered**). Written a week before the weights actually dropped and explicitly framed as a fact-check ("everything that survived… and nothing that didn't") against Moonshot's technical blog, Artificial Analysis, LMArena and launch-week coverage — which makes it the right artefact to read *now* that the 2.8T weights are downloadable and the claims can be tested independently. 13 head-to-head benchmarks, a 10-scenario decision guide, working API code, and an explicit list of what the model still cannot do. The opening anecdote is the one that travels: K3 spent 48 hours autonomously designing a silicon chip — floorplan, timing closure at 100 MHz, 1.46M standard cells, an INT4 multiply-accumulate array — with open-source EDA tools, to run a nano version of itself. Caveat for anyone planning to self-host: Moonshot's own recommendation is supernode configurations of at least 64 accelerators, so "open weights" and "you can run this" remain different statements. Member-only story; the TL;DR and framing are readable without a subscription.

### rag / retrieval-augmented-generation / vector-database
- **[OKF + RAG: The Ultimate AI Agent Architecture](https://medium.com/@ravishkhullar/okf-rag-the-ultimate-ai-agent-architecture-26b9ceed44f1)** — Ravish Khullar (Jul 4; **not previously covered**). Picked up today because it is the conceptual pair to the LangChain data-stack post above and to LangChain's own OpenWiki 0.2 OKF adoption (Jul 16). The argument is a clean, non-obvious split: RAG is *probabilistic* — it finds documents that are semantically similar, not factually authoritative — which is fine for reach across unstructured archives and wrong for the exact churn formula, the precise API contract, the database-failover runbook. Google Cloud's **Open Knowledge Format** (introduced June 2026) answers that with something deliberately boring: a Git directory of Markdown files with YAML frontmatter, one concept per file, no embeddings, no chunking strategy, no vector DB, no re-indexing — and therefore a full PR/commit audit trail of who changed the churn definition and why. The hybrid is an intelligent router: deterministic OKF path first, probabilistic RAG fallback, with a working Python implementation included. The analogy that makes it stick is the new hire on day one handed both a curated company wiki *and* a search engine over every Slack thread — neither is sufficient alone.
