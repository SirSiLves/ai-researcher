## Medium roundup

### rag
- **[How AI Agents Learned to Think: The Reinforcement-Learning Recipe Behind Agentic RAG and Deep Research in 2026](https://buzzgrewal.medium.com/how-ai-agents-learned-to-think-the-reinforcement-learning-recipe-behind-agentic-rag-and-deep-0cd3663c9bf6)** — Abdullah Grewal (Jul 2026). Argues retrieval is shifting from prompt-orchestrated "agentic RAG" to search agents trained end-to-end with RL that decide for themselves when to query, what to ask, and when they know enough to stop — evidenced by Moonshot's Kimi-Researcher climbing 8.6% → 26.9% on Humanity's Last Exam almost entirely through end-to-end RL. A data-backed argument about where retrieval is heading, not a framework tour.

### ai-engineering
- **[Trace Is Evals: Data Engineering for Agent Trace Analysis and Attribution](https://medium.com/@databend/trace-is-evals-data-engineering-for-agent-trace-analysis-and-attribution-9c173e8ce657)** — Databend (Jul 2026). Position piece: final pass/fail is not enough to evaluate an agent — you need the full execution trace, and that turns eval into a data-engineering problem (cleaning, splitting, indexing, aggregating, and querying long-running traces for attribution) requiring a data layer distinct from a traditional observability backend.
- **[AI Observability Pipelines: Knowing What Your Agent Actually Did](https://medium.com/@srinib100/ai-observability-pipelines-knowing-what-your-agent-actually-did-8a4fc8f7affe)** — Srinivas Bommena (Jul 2026). Complementary angle: frames an observability pipeline as the machinery that turns every meaningful agent run into comparable evidence — a workflow trace plus cost/latency measurements, behavioural-drift signals, and quality scores that can be diffed across releases, models, prompts, and user segments.

### ai-safety
- **[Your AI Agent Has No Safety Net: Agentic Guardrails, Layered Defense](https://medium.com/@nuno.roberto/your-ai-agent-has-no-safety-net-f594a5112fe2)** — Nuno Roberto (Jul 2026). Defense-in-depth argument for autonomous agents: one guardrail is not a safety net, so it lays out layered runtime controls (input sanitization, tool/permission gating, output validation, monitoring) that stop an agent from compounding a small error into a real liability.
