**[Claude Code is steganographically marking requests](https://thereallo.dev/blog/claude-code-prompt-steganography)** — 2435 pts · 746 comments · ~5 days ago · `thereallo.dev` · [HN discussion](https://news.ycombinator.com/item?id=48734373)

_What this is:_ A reverse-engineer found Claude Code embeds a hidden steganographic fingerprint (invisible zero-width / whitespace patterns) into outgoing requests, apparently to detect distillation and account reselling. Undisclosed until this write-up. This is the single highest-signal AI thread of the scan window and the root of a multi-story arc (see the Alibaba ban and the CVE-spike items below).

_Comment signal:_
- @LPisGood: combating resellers/distillation is genuinely hard; these are just standard anti-observation techniques, and sophisticated actors will patch the binary anyway.
- @MattDamonSpace: "So the feature mostly punishes the exact people who are easier to fingerprint — normal developers doing weird but legitimate things. What's the punishment here exactly?"
- @theplumber: "The more I learn about Anthropic the more they disgust me."
- _Notable critique:_ The thread splits into "reasonable anti-distillation defense" vs "the problem is that it was hidden in a tool that asks for full filesystem + terminal access." Sharpest take (the asymmetry argument): a steganographic classifier only catches unsophisticated users while anyone with a motive patches it in five minutes — "a security control that operates entirely on the people it should not be operating on."

_What this is:_ A GitHub issue (openai/codex) showing GPT-5.5 responses disproportionately cluster at reasoning_output_tokens = 516 (and 1034, 1552 — multiples of ~518), correlated with errors on complex tasks. 82% of exact-516 events came from GPT-5.5 despite it being 19.3% of the sample.
