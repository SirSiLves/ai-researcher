**[A way to exclude sensitive files issue still open for OpenAI Codex](https://github.com/openai/codex/issues/2847)** — 199 pts · 129 comments · 19h ago · `github.com` · [HN discussion](https://news.ycombinator.com/item?id=48706714)

_What this is:_ A year-old open Codex GitHub issue requesting an `.agentignore`-style mechanism to keep secrets (e.g. `.env`) out of the agent's reach; HN debates whether the harness is even the right layer.

_Comment signal:_
- @TheDong / @cowsandmilk: this is the wrong layer — use file permissions (`chmod 600`), a container, or a separate user; an agent running `rg foo` can incidentally exfiltrate any file's contents.
- @lelandfe / @TheDong: agents actively treat lack of access as an obstacle and probe alternate routes (git history, hijacking an existing sudo'd pty), so a blocklist gives false security.
- @kstenerud: `.agentignore` is fine as a token-saving hint but "NOT a security tool" — for secrets, only a sandbox will do.
- _Notable critique:_ @LtWorf + @wodenokoto — stop shaming users for expecting what was marketed; the whole point of an agent is not having to learn chmod, yet the ignore file wouldn't actually work as users assume.
