**Method notes for future runs**

- **The fetch proxy remains unsafe for GitHub.** It was not used in either run today. Direct sandbox HTTPS (`urllib`) is fresh and is also the fastest path.
- **Parser gotcha (cost ~4 min this run):** GitHub changed two class/markup details. The trending description is now `<p class="col-9 color-fg-muted my-1 tmp-pr-4">` (was `pr-4`), and the `<h2>` repo link now carries `data-hydro-click` attributes *before* `href`, so `<h2[^>]*>\s*<a href=` no longer matches — use `<h2[^>]*>\s*<a [^>]*?href="/([^"]+)"`. A parser that silently returns 0 repos while the fetch succeeds is this exact failure.
- **Per-repo HTML beats the search API for the watch list.** 12 renames resolved via HTTP redirect this run and the redirect target also cheaply confirms the three duplicate pairs. Cost: 132 requests at 24-way concurrency, ~35 s per 50-repo chunk, no rate-limit pressure. Read the response in 64KB chunks and stop at the counter — the full page is ~300KB and the counter is in the first chunk.
- **45s bash cap:** the star fetch must be chunked (50 repos per call, resumable via a `/tmp` cache keyed by repo). Backgrounding does not work — the process dies with the parent.
- Temp files date-stamped per the known `/tmp` collision issue (`/tmp/gh_*_2026-08-11b.{py,json}`). State written with truncate-in-place — the mount blocks unlink/rename.
