The theme today is **agent state**: where it lives, who is allowed to write it, and what it costs to read. Three independent papers move task state, memory or stored text *out* of the growing context and into an explicitly governed store — and two of them show that doing so is what actually buys the reliability or the safety.

## Top picks

**LongHorizon-Harness: Advancing Long-Horizon Agents for Real-World Tasks** — Ziyu Ma, Hailang Huang, Shun Zou et al. (AMAP-ML)
_Takeaway:_ Reformulates long-horizon execution as a task-state management problem rather than a context problem. Its Manage-Execute-Audit loop keeps task state outside execution and updates it only with facts independently verified from the environment — a manager picks the next subtask, a fresh-context executor runs it, a read-only auditor verifies the resulting environment state before the next round. Lifts Qwen 3.7-Plus from 51.8% to 80.7% on WeaveBench, 69.7% to 77.2% on Terminal-Bench 2.1, 2.8% to 8.3% on OSWorld 2.0, and Claude Opus 4.7 from 20.0% to 34.3% on an OSWorld 2.0 subset. A lightweight AgentAdapter makes model and harness backends interchangeable without touching their native agent loops. Today's top agent paper on HF (55 upvotes).
_Category:_ arXiv 2608.01964. https://arxiv.org/abs/2608.01964

**ScrambleToolBench: Agents Search Exhaustively Even When Their Own Map Points to the Next Step** — Vernon Toh, Navonil Majumder, Zhengyuan Liu, Nancy F. Chen, Soujanya Poria (DeCLaRe Lab)
_Takeaway:_ Strips the semantic cues out of tool schemas so agents must discover hidden tool behaviour purely by interaction, then perturbs the environment mid-run with mapping drift, stochastic action failures and temporal execution windows. The finding is the sharp one: successful initial discovery does not transfer to robust adaptation. Under structural change agents fail to apply deductive strategies like cycle tracing, showing belief inertia or falling back to exhaustive search — and *increasing test-time reasoning only amplifies the brute-force search* rather than enabling deductive recovery. Persistent memory reduces compounding errors but still doesn't let them infer structural change efficiently.
_Category:_ arXiv 2608.02358 (cs.AI). https://arxiv.org/abs/2608.02358

**MAPLE-Guard: Memory-Aware Link Enforcement Against Memory-Link Poisoning in Multi-Agent Systems** — Wenjun Xiong, Yijin Zhou, Jiaqian Wang et al.
_Takeaway:_ Persistent agent memory as a durable attack channel: one poisoned write is retrieved repeatedly in later tasks, promoted into shared memory, and reused by agents that never saw the original attack — with no malicious message crossing a visible communication edge at the moment of harm. Because existing safeguards inspect prompts, actions or edges, they miss content that is benign at write time and harmful after retrieval. MAPLE-Guard gates the whole memory lifecycle (write, retrieval, promotion, cross-agent reuse), cutting attack success from 38.2% to 0.9% on LongMemEval and 34.7% to 0.2% on AppWorld, while raising multi-agent defense success from 54.0% to 74.3% and 42.5% to 99.8%.
_Category:_ arXiv 2608.00426 (cs.MA / cs.CR). https://arxiv.org/abs/2608.00426

**SKT: Skill-Use Training at Scale via Verified Synthetic Data Generation** — Zelin Tan, Yiqun Zhang, Hao Li et al. (Shanghai AI Laboratory)
_Takeaway:_ Names the gap that "agent skills" packaging leaves open — handing a model reusable procedural knowledge does not mean it can identify, apply and coordinate it. SKT synthesises skill-grounded tasks and executable trajectories from a skill library, using rule-based and agent-based verification with feedback-guided repair, and keeps only trajectories that substantially exercise every required skill. From 2,000 public skills it yields 4,000 task packages and 27,164 verified trajectories, plus SkillEval, a held-out executable benchmark built from a disjoint skill pool. SFT on the output improves skill use across models, benchmarks and harnesses; ablations show the gains depend on verification quality and grow with skill coverage.
_Category:_ arXiv 2608.02287. https://arxiv.org/abs/2608.02287

**Token-Native Storage: Read and Write in your Agent's Language** — Kumar Shivendu
_Takeaway:_ Argues the storage layer is still built for the wrong reader: engines keep text as UTF-8 while embedders, rerankers and agents all work in token IDs, so every access pays a translation tax. Storing BPE token IDs directly is both smaller and faster — uint16-packed r50k beats UTF-8 by 2.25x uncompressed and 3.30x with an entropy coder, and across six tokenizers and three corpora (English, code, Hindi) compressed token IDs match or beat every byte codec including a corpus-trained zstd dictionary. Serving IDs straight to the model instead of re-tokenizing on each read is ~10–600x faster. Also a concrete interop ask: BPE numbers tokens by merge order rather than frequency, and re-ranking by frequency lets plain streamvbyte recover most of the entropy coder's ratio at ~7x faster decode — a one-line change the author asks labs to make when publishing vocabularies, alongside a call for a shared standardized vocabulary.
_Category:_ arXiv 2608.02376 (cs.DB / cs.CL / cs.IR). https://arxiv.org/abs/2608.02376

**Securing Agentic AI: From Per-Action Checks to Trajectory Assurance** — Alireza Lotfi, Subangkar Karmaker Shanto, Imtiaz Karim, Elisa Bertino
_Takeaway:_ Position paper (ACM AI Leadership Summit 2026) making behavioral containment the central agent-security problem: safety is determined not by the correctness of individual actions but by whether the overall trajectory stays inside the system's rules and invariants — sequences of individually permissible actions can collectively violate them. Maps the attack surface across the full agentic stack: untrusted inputs via prompts, memory, retrieved knowledge and tool interfaces at the single-agent level; identity, trust, capability control and decision transparency once delegation crosses organizational boundaries; a model-routing and execution control plane vulnerable to manipulation and unverified model provenance; and supply-chain integrity, accountability and end-to-end observability as still-open problems. The unifying claim: security must be a verifiable property of the architectures, protocols and runtimes, not an advisory layer.
_Category:_ arXiv 2608.01558 (cs.AI / cs.CR / cs.MA). https://arxiv.org/abs/2608.01558

## Other interesting items

- **[Fetch-then-Explore: Decoupling Selection from Extraction over a Persistent Workspace for Search Agents](https://arxiv.org/abs/2608.02097)** — Qi Liu, Yiqun Chen, Zidan Chen et al. incl. Jiaxin Mao, Tat-Seng Chua. Splits a search agent's two jobs — choosing what to fetch and extracting from what was fetched — across a persistent workspace rather than one growing context. Same group posted a companion diagnosis paper today. (cs.AI / cs.IR)
- **[Diagnosing Search Behavior and Failure Modes in Long-Horizon Search Agents](https://arxiv.org/abs/2608.01913)** — Qi Liu, Jiaxin Mao, Fengbin Zhu, Tat-Seng Chua. The failure-mode analysis paired with the above; the pairing of a diagnosis paper with an architecture paper from the same authors on the same day is the useful signal. (cs.AI / cs.CL / cs.IR)
- **[V-Mem: Modality-Routed Retrieval for Long-Term Multimodal Agentic Memory](https://arxiv.org/abs/2608.01543)** — Dingyi Kang, Dongming Jiang, Yi Li, Guanpeng Li, Bingzhe Li. Routes retrieval by modality for long-term agent memory; 19 pages, 16 tables, code at github.com/Dingyi-Kang/V-Mem. (cs.AI / cs.CL / cs.CV / cs.IR)
- **[Verification Without Sufficiency: Per-Chunk Filtering Fails on Multi-Hop RAG, and Decomposition Repairs It](https://arxiv.org/abs/2608.00585)** — Randhir Kumar. Argues the standard per-chunk relevance filter is the wrong unit for multi-hop RAG, since no single chunk is sufficient, and that query decomposition restores it. Ships per-question traces and analysis scripts. (cs.CL / cs.IR / cs.LG)
- **[Progressive Agent Skill Generation via Reinforcement Learning](https://arxiv.org/abs/2608.01678)** — CUHK Database Group. The RL counterpart to SKT above — generating the agent skill library itself rather than training on a fixed one. 24 upvotes on HF today.
- **[UEmbed: Unified Sparse and Dense Multimodal Embeddings](https://arxiv.org/abs/2608.02583)** — Tingyu Song, Mingxin Li, Yanzhao Zhang et al. (Alibaba-NLP). Single model producing both sparse and dense multimodal embeddings, aimed at hybrid retrieval stacks that currently run two. 16 upvotes on HF. (cs.CV / cs.AI / cs.CL / cs.IR)
- **[SWE-Touch: Benchmarking Coding Agents When Users Touch the Code](https://arxiv.org/abs/2608.02499)** — CASIA. Coding-agent evaluation under concurrent human edits, rather than the usual assumption that the agent is the only writer — the axis most SWE benchmarks hold fixed. 14 upvotes on HF.
- **[Can LLM Agents Price Competitively? A Dynamic Multi-Attribute Auction Benchmark for Agentic Commerce](https://arxiv.org/abs/2608.00102)** — Shimaa Ahmed, Yiwei Cai, Mohsen Minaei, Rahul Rachuri. Agentic-commerce benchmark on dynamic multi-attribute auctions; relevant to the collusion/competition questions regulators have started asking about agent-set prices. (cs.AI / cs.MA)
- **[DiffusionGemma Technical Report](https://arxiv.org/abs/2608.00146)** — Google DeepMind. Diffusion-based entry in the Gemma line, posted to HF Papers today.
