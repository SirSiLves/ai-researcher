## Top picks

**CoinRAG: Contextualized Information Nugget KV Cache Reuse for Long-Context RAG** — Gyuwan Kim, Cheoneum Park, Tao Yang.
_Takeaway:_ Goes finer-grained than chunk-level KV cache reuse: a two-stage retrieval picks query-relevant semantic units inside each chunk and assembles their sliced KV representations, cutting prefill cost while gaining 5.3% relative F1 on LongBench multi-hop QA — the prefill-cost lever that decides whether long-context RAG is affordable in production. _Category:_ 2608.07458 (cs.CL; cs.AI; cs.IR; cs.LG). https://arxiv.org/abs/2608.07458

**LLMRouter: Unified Infrastructure for Developing, Evaluating, and Deploying LLM Routers** — Tao Feng, Fangxu Yu, Haozhen Zhang, Zhongjie Dai, Liangqi Yuan, Zijie Lei, Weizhi Zhang, Kunlun Zhu, Haodong Yue, Keyang Xuan, Ge Liu, Jiaxuan You.
_Takeaway:_ A single framework covering the whole router lifecycle — train, benchmark, serve — rather than another one-off routing heuristic; this is the platform layer that last week's "when does orchestration pay off" result implies you need. _Category:_ 2608.06867 (cs.CL). https://arxiv.org/abs/2608.06867

**The Horizon Gap: Planning, Memory, Execution, Training, and Evaluation for Long-Horizon LLM Agents** — Mingguang Chen, Licheng Wang, Bo Qu.
_Takeaway:_ Surveys 1,547 papers (2024–2026) and does the disambiguation the field keeps fudging — long-horizon (task property) vs. long-context (model property) vs. long-term memory (system property) — then finds one pattern everywhere: outcome-only signals go uninformative as horizons lengthen, and every fix (process reward models, credit assignment, trajectory diagnostics) is really manufacturing denser step-level signal. Closes on the measurement problem that matters commercially: you cannot currently separate model capability from harness capability. _Category:_ 2608.06663 (cs.CL). https://arxiv.org/abs/2608.06663

**From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL** — Jiaqian Wang, Yutao Qi, Wenjin Hou, Yuanxi Che, Muning Wen (Xidian University; Shanghai Jiao Tong University).
_Takeaway:_ Asks whether expensive test-time search can be "crystallized" into reusable memory so the second run is cheap — the economic question behind every agent-memory product, measured on a concrete task with code and reproduction artifacts released. _Category:_ 2608.07213 (cs.CL). https://arxiv.org/abs/2608.07213

**DocMemo: Dynamic Evidence Discovery via Probabilistic Memory-Guided Retrieval for Multi-Modal Document Understanding** — Hanshu Yao, Janfeng Zhong, Niu Lian, Jinpeng Wang.
_Takeaway:_ Tri-level memory plus dynamic Bayesian belief updating replaces static top-K retrieval for long-document reasoning, so evidence is tracked across the document rather than re-fetched blind at each step. _Category:_ 2608.07067 (cs.AI; cs.CL; cs.IR; cs.MM). https://arxiv.org/abs/2608.07067

**DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds** — Kishanthan Thangarajah, Boyuan Chen, Ahmed E. Hassan (Waterloo / Centre for Software Excellence).
_Takeaway:_ The sharpest agent-interoperability result of the batch. CLI coding agents have all converged on one training environment (OpenHands), and models fine-tuned there score well under OpenHands but **degrade substantially under any other scaffold** — while untrained base models show no such divergence, so the gap is fine-tuning-induced, not capability. DCAS is an interception layer that swaps backends under any scaffold without modifying it, enabling honest cross-scaffold evaluation. The diagnosis: planning structure is currently a scaffold artifact and needs to become a learned model capability. This is empirical evidence that "agent benchmark scores" are partly harness lock-in. _Category:_ 2608.06113 (cs.SE; HF Daily Papers 2026-08-10). https://arxiv.org/abs/2608.06113

**The Optimizer Is the Agent: Reasoning-Driven Search across Prompts, Programs, and ML Workflows** — Junbo Li et al. (8 authors).
_Takeaway:_ Unifies prompt optimization, program synthesis and ML-workflow tuning as one reasoning-driven agentic search problem rather than three separate toolchains — the natural generalization of DSPy-style optimizers. _Category:_ 2608.06714 (HF Daily Papers 2026-08-10). https://arxiv.org/abs/2608.06714

**Zero Gap Is Not Restoration: Stratified Per-Question Probability Evaluation and Step-wise Mitigation of Benchmark Contamination** — Ruijie Hou, Yueyang Jiao, Zhao Wang, Yingming Li (Zhejiang University).
_Takeaway:_ Shows that closing the contamination gap on aggregate is not the same as restoring an uncontaminated benchmark, and gives a per-question stratified probability test instead — directly useful ammunition when a vendor waves a benchmark score. _Category:_ 2608.07341 (cs.CL; cs.AI). https://arxiv.org/abs/2608.07341

**Exact Adaptive Hybrid Retrieval Without Fixed Top-L Cutoffs** — Chunran Zhang.
_Takeaway:_ Drops the arbitrary top-L truncation in hybrid sparse+dense retrieval while keeping exactness, removing a tuning knob that quietly caps recall in most production RAG stacks. _Category:_ 2608.07152 (cs.IR). https://arxiv.org/abs/2608.07152

**Skaling: Chinchilla's Exponents Meet Kaplan's Coupling** — Mathurin Videau, Badr Youbi-Idrissi, David Lopez-Paz, Kartik Ahuja (AI at Meta).
_Takeaway:_ Reconciles the two canonical scaling-law families that have disagreed for four years — the kind of result that changes how compute budgets get argued about internally. _Category:_ 2608.07222 (cs.CL). https://arxiv.org/abs/2608.07222

**When Privileged Guidance Misaligns: State-Matched Routing and Contextualized Self-Distillation for Multi-Turn Agents** — 4 authors.

**LLM within MCP Matters: Measuring Inefficient Resource Utilization Driven by LLMs** — Minhan Cho, Soyoung Park, Kihyeon Jeong, Byeongkyu Jeon, Daejin Choi, Jinyoung Han.
_Takeaway:_ The most directly actionable MCP result yet. A 54,000-trial study across 24 models (9 Claude, 6 Gemini, 9 GPT) on a production legal-information MCP server tests whether clients actually use reference data embedded in *server instructions* — and they largely don't, preferring to re-discover the same facts through a search tool. The diagnostic condition is the punchline: remove the competing search tool and 23 of 24 models read the embedded data reliably, so this is **behavioural preference, not missing capability**. Anyone designing MCP servers is currently paying for tool calls that the instruction payload already answered. _Category:_ 2608.08467 (cs.AI; cs.CL; cs.IR). https://arxiv.org/abs/2608.08467

**MasDrift: Benchmarking Authorization Preservation Across Multi-Agent Architectures** — Zhuoning Xu, Xiucheng Zhang, Hanjun Luo, Yingbin Jin, Yinpeng Dong, Hanan Salam.
_Takeaway:_ Asks the governance question that adversarial red-teaming misses: when a supervisor delegates a goal, does the *authorization boundary* travel with it? 600 benign productivity tasks across eight domains, each pairing required work with reserved actions. Centralized hierarchies win on completion (93.9–98.6% vs 85.7–87.0% for peer networks) but lose badly on authorization — unauthorized actions in 2.7–19.8% of tasks versus 0.6–0.8% for peer networks, and the gap **widens with hierarchy depth**. A concrete completion-vs-containment trade-off curve for anyone picking a multi-agent topology. _Category:_ 2608.07556 (cs.MA; cs.AI). https://arxiv.org/abs/2608.07556

**Evo-Bench: Can Language Models Improve Agent Harness?** — Lisheng Huang, Chen Yang, Hao Zhou, Huatong Song, Zongchao Chen, Ran Le, Yang Song et al.
_Takeaway:_ The direct empirical follow-on to DCAS above. Where DCAS showed harness is a confound, Evo-Bench makes harness *the measured object* — can a model autonomously optimize its own operating harness, across Search, Office and General agent domains? Its construction framework specifically isolates harness improvement from base-model strength via auxiliary-task evolution, which is exactly the separation the Horizon Gap survey said the field cannot currently make. _Category:_ 2608.09096 (cs.CL). https://arxiv.org/abs/2608.09096

**Beyond Tier Labels: Role- and Deployment-Dependent Model Substitution in Multi-Call LLM Workflows** — Renxiang Wang, Jiaming Cui.
_Takeaway:_ Sharpens LLMRouter's problem statement: query-level routing is the wrong granularity, because a model's value depends on *where in a dependent computation it is called*. Tested on controlled solve-merge-verify workflows of 8–64 solve calls across four three-tier model ladders, with a predicate-action factorization that separates "where to spend the strong model" from "what the substitution is actually worth". Ladder composition flips the answer — all-strong cuts RMSE 4.818 → 1.538 on a mixed Qwen/GPT ladder while the Qwen-only ordering reverses — so vendor-agnostic routing heuristics are unsafe. _Category:_ 2608.09155 (cs.MA). https://arxiv.org/abs/2608.09155

**Muscle Memory for Agents: Compile not Merely Retrieve** — Pouya Ghiasnezhad Omran, Soujanya Lanka, Qin Zhang, Tanya Dixit.
_Takeaway:_ A position paper with teeth, and the natural companion to today's crystallization result. Argues agent memory has over-converged on one pattern (store text/embeddings/reflections → retrieve → let a general orchestrator interpret) and that for personalization the right move is **compiling recurring user intent into purpose-built specialist agents**. Backed by a four-phase Harvest → Analyze → Augment → Evaluate pipeline that mines conversation history. Targets the "multi-turn tax" — users repeatedly correcting format, depth and scope. _Category:_ 2608.08995 (cs.MA). https://arxiv.org/abs/2608.08995

**SuperLocalMemory 4.0: The Governed Memory Operating System for AI Agents** — Varun Pratap Bhardwaj, Garima Singh, Arun Pratap Bhardwaj.
_Takeaway:_ The rare agent-memory paper written for a regulated buyer rather than a benchmark. Fuses dense/BM25/temporal/Hopfield-associative/spreading-activation retrieval via reciprocal-rank fusion, then wraps it in the compliance layer everyone else omits: bi-temporal recall, personal/shared/global scoping, RBAC, **GDPR-oriented export and verified erasure**, audit trails, and a deployment-context **EU AI Act checklist**. V4 adds a reliability spine — generation-fenced admission, policy registry, verifiable memory transactions with apply/verify/compensate/erase owners, hash-checkable completion manifests. _Category:_ 2608.08253 (cs.AI; cs.IR). https://arxiv.org/abs/2608.08253

**SkillSentry: Reliable Skill Execution for LLM Agents via Runtime Assurance** — You Lu, Xinyu Huang, Bihuan Chen, Xin Peng (Fudan).
_Takeaway:_ Runtime assurance for agent skill execution — the enforcement-side counterpart to today's two skill-poisoning attack papers, and a candidate primitive for an agent runtime standard. _(Title verified against the abs page; abstract not fetched this run.)_ _Category:_ 2608.09253 (cs.AI). https://arxiv.org/abs/2608.09253

**KVDiagnosis: A Diagnostic Benchmark for KV-Cache Compression in Long-Context Language Models** — Chen Qiu, Ziwu Liu, Chao Fei, Guozhong Li, Panos Kalnis (KAUST).
_Takeaway:_ The diagnostic counterpart to CoinRAG: if you are going to reuse and compress KV cache to make long-context RAG affordable, this is the benchmark that tells you what the compression silently broke. _(Title verified against the abs page; abstract not fetched this run.)_ _Category:_ 2608.09412 (cs.AI). https://arxiv.org/abs/2608.09412
