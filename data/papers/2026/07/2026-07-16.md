# AI Papers — 2026-07-16

_Collector: ai-papers. Slice: ArXiv (cs.CL, cs.AI, cs.LG, cs.MA, stat.ML, cs.IR), HF Papers, papers.cool._

## Top picks

- **Ring-Zero: Scaling Zero RL to a Trillion Parameters for Emergent Reasoning** — cs.CL submission. _Takeaway:_ Scales "zero RL" (RL with verifiable rewards, no human labels) to a 1-trillion-parameter model via a stability pipeline — clipped importance sampling, training-inference ratio correction, mixed-precision control. Reports advanced cognitive behaviors (self-verification, parallel reasoning, structured formatting) emerging spontaneously at scale and a discovery→sharpening training progression — one of the first public looks at RL dynamics at the 1T frontier. _Category:_ arXiv:2607.12395 (cs.CL). [https://arxiv.org/abs/2607.12395](https://arxiv.org/abs/2607.12395)

- **Agora: Collective and Permissionless Internet-Scale Pretraining of Large Language Models** — cs.LG submission. _Takeaway:_ "Protocol Learning" shards a model pipeline-parallel across heterogeneous, preemptible consumer GPUs over the internet, so no single party ever holds the full weights. Demonstrates Pluralis-8B — an 8.6B model trained on 500B FineWeb-Edu tokens by 330 volunteer nodes over 40 days at ~63% of a centralized H100 baseline's efficiency. A concrete challenge to the assumption that frontier pretraining must be datacenter-bound. _Category:_ arXiv:2607.13332 (cs.LG). [https://arxiv.org/abs/2607.13332](https://arxiv.org/abs/2607.13332)

- **Where Should RL Post-Training Compute Go? Model Size, Search, Learning, and Feedback** — cs.LG submission. _Takeaway:_ A FLOP-accounting framework for GRPO that decomposes post-training compute into rollout/search, policy-update/learning, and reward-model evaluation, then asks where a fixed budget is best spent. Finds conditional allocation frontiers — the optimal split shifts with model size, budget, and reward type (rule-based vs. PRM) — and argues RL papers should report how FLOPs are divided, not just the total. _Category:_ arXiv:2607.13389 (cs.LG). [https://arxiv.org/abs/2607.13389](https://arxiv.org/abs/2607.13389)

- **Learning Latency-Aware Orchestration for Multi-Agent Systems (LAMaS)** — cs.MA submission. _Takeaway:_ Latency-aware orchestration for LLM multi-agent systems: learns latency-aware execution graphs with critical-path-aware credit assignment at training time, plus a lightweight runtime controller that adaptively prunes redundant agent interactions. Cuts end-to-end latency by >50% while holding or improving accuracy, and transfers across MAS with minimal changes. _Category:_ arXiv:2607.13359 (cs.MA). [https://arxiv.org/abs/2607.13359](https://arxiv.org/abs/2607.13359)

- **AgentCheck: A Reproduce-Intervene-Mitigate Workbench for LLM Agents over MCP** — cs.CL/cs.SE submission. _Takeaway:_ Turns an MCP server into a fault-injection surface for tool-using agents: records real tool responses, then replays them perturbed by 12 fault types (timeouts, stale values, poisoned descriptions) for a reproduce-intervene-confirm loop that tests mitigations before deployment. Across five agents, failures are usually silent, confident use of bad tool outputs; a retry fixes timeout faults but stale-data faults persist. Squarely in the MCP / agent-observability lane. _Category:_ arXiv:2607.11098 (cs.CL). [https://arxiv.org/abs/2607.11098](https://arxiv.org/abs/2607.11098)

- **Oracle Agent Memory as an Enterprise Memory Substrate for Long-Horizon AI Agents** — cs.AI submission. _Takeaway:_ Frames agent memory as a database-native lifecycle (ingest→extract→consolidate→retrieve→summarize→revise) on Oracle Database, with explicit scope control across users, agents, and threads. Reaches 93.8% on LongMemEval while using ~10.7x fewer tokens than flat-history baselines — a vendor's argument for memory as an enterprise substrate rather than plain document retrieval. _Category:_ arXiv:2607.13157 (cs.AI). [https://arxiv.org/abs/2607.13157](https://arxiv.org/abs/2607.13157)

- **Final Authority in AI Governance: Frontier-Provider Sovereignty and Action-Centered Deployer Governance** — cs.AI submission. _Takeaway:_ Policy analysis of where final authority should sit for high-impact agent actions: frontier-provider sovereignty vs. action-centered deployer sovereignty. Reading the EU AI Act, NIST AI RMF, Singapore's agentic-AI framework, and Japanese/Canadian instruments, it finds stronger support for distributed operational accountability — final authority with the deployer/consequence-bearer, upstream authority reserved for frontier-capability gating. _Category:_ arXiv:2607.13040 (cs.AI). [https://arxiv.org/abs/2607.13040](https://arxiv.org/abs/2607.13040)

- **Cluster with Auctions for Vector Search (CwA)** — cs.IR submission. _Takeaway:_ Decouples the query probing function from the database partition in approximate nearest-neighbor search, jointly learning a balanced partition (via a parallelizable auction algorithm) and a neural probing function optimized for the query distribution. Up to 4.7x throughput at equal recall when query and database distributions differ. From Meta FAIR (Douze, Jégou et al.) — relevant to any production vector-store stack. _Category:_ arXiv:2607.13728 (cs.IR). [https://arxiv.org/abs/2607.13728](https://arxiv.org/abs/2607.13728)

## Other interesting items

- **[AgentCompass: A Unified Evaluation Infrastructure for Agent Capabilities](https://arxiv.org/abs/2607.13705)** — cs.AI. Open-source agent-eval infra splitting evaluation into Benchmark/Harness/Environment with a fault-tolerant async runtime and trajectory tools to diagnose failure modes like reward-hacking; natively supports 20+ benchmarks across five capability dimensions.
- **[Transforming LLMs into Efficient Cross-Encoders via Knowledge Distillation for RAG Reranking](https://arxiv.org/abs/2607.11933)** — cs.CL. Fine-tunes LLaMA-3-8B (LoRA + 4-bit) as a drop-in RAG reranker, beating a cross-encoder baseline by 14–21% across RAGAS metrics without the quadratic inference cost.
- **[MemOps: Benchmarking Lifecycle Memory Operations in Long-Horizon Conversations](https://arxiv.org/abs/2607.12893)** — cs.CL. Reframes conversational-memory evaluation as lifecycle operations (remember / forget / update / reflect) with gold operation traces, exposing failures that final-answer QA hides — e.g., long-context models are weak at reconstructing ordered memory-state trajectories.
- **[TRACE: Turn-level Reward Assignment via Credit Estimation for Long-Horizon Agents](https://arxiv.org/abs/2607.13988)** — cs.LG. Dense per-turn credit assignment for agentic RL using TD changes in frozen reference-model log-ratios (no extra critic), lifting Qwen3-4B from 7.2 to 35.6 on closed-web BrowseComp-Plus via pure RL with no SFT cold-start.
- **[CAVA: Canonical Action Verification and Attestation for Runtime Governance of Agentic AI Systems](https://arxiv.org/abs/2607.13716)** — cs.AI. Proposes canonical action identity/attestation so a single operational act (publish code, move money, export data) is reproducibly verifiable across heterogeneous runtimes (coding hooks, SDK tools, browser automation, gateways) — a governance primitive for "what was actually approved."
- **[The Refusal Residue: When Probes Catch Alignment Faking and When They Don't](https://arxiv.org/abs/2607.13346)** — cs.AI. Asks whether hidden states reveal alignment faking that outputs conceal when no scratchpad is visible — mapping when activation-space probes do and don't separate strategic from genuine compliance.
- **[What Models Express, Suppress, and Resist: Auditing Open-Weight LLMs with Persona Vectors](https://arxiv.org/abs/2607.13162)** — cs.AI. First large-scale persona-vector study: a 53-trait inventory labels each trait natural / steerable / intractable across two open-weight models, finding both default to helpful task-oriented behavior and that steering helps most on excluded traits (hyperbole, hallucination, sycophancy).
