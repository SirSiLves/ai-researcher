## Top picks

**Metis: Memory Foundation Model** — Zeyu Zhang, Ziliang Guo, Yihang Sun, Xichong Zhang, Xixuan Hao, Zehao Lin, et al. (17 authors). _Takeaway:_ The most architecturally consequential paper of the day, and a direct challenge to how every agent platform currently does memory. The observation is simple: agents have internalized multimodality and reasoning into the foundation model itself, but **memory is still an external module** — a vector store, a retrieval layer, a scratchpad bolted on outside the weights. Metis proposes the first *memory foundation model*, formalizing native memory as two things: a **persistent, dynamically evolving memory state inside the backbone**, and native memory procedures that store and retrieve through model computation rather than an external call. Historical information is compressed into the model and accessed through **memory attention**; the procedures are acquired through mid-training on large-scale memory-specific data with multiple objectives. The two properties that make this deployable rather than academic: online memory maintenance is **gradient-free** and a memory update needs only a **forward pass**, and at inference all learned weights stay **frozen** while the native memory state transforms through standard forward computation. Project and model checkpoints released, with an explicit analysis of limitations. If native memory works, the retrieval-layer-as-memory design that most agent stacks are built on becomes a transitional architecture. Second-highest-upvoted paper on HF today (211). _Category:_ cs.CL / cs.LG — 2607.26760. [link](https://arxiv.org/abs/2607.26760)

**Qwen-UI-Agent Technical Report: Toward Next-Generation Real-World Centric Foundation GUI Agents** — Hanzhang Zhou, Panrong Tong, Xu Zhang, Quyu Kong, Chenglin Cai, Tianyu Xia, et al. (16 authors). _Takeaway:_ The day's frontier-capability datapoint, and the numbers are stated against named competitors. Qwen-UI-Agent spans mobile, computer-use, web and DeepSearch, with a **unified action space that interleaves GUI operations with CLI execution** and emits batched actions in a single model turn — the design choice worth stealing, since it stops the agent from paying a full decode round-trip per click. Training combines sandbox environments with a large-scale **real-device mobile runtime**, an AutoResearch-style data flywheel where agents construct tasks and environments and diagnose their own failures, and online RL over trajectories **exceeding 100 turns** with **10,000+ concurrent environments** for rollout. It sets state of the art on mobile use — 82.1% MobileWorld, 92.2% MobileWorld-Real, 97.5% AndroidDaily — and stays competitive with **Opus 4.8, Gemini 3.1 Pro and GPT-5.6 Sol** on computer and browser use: 79.5% OSWorld-Verified, 40.0% partial progress on OSWorld-v2, 73.6% WebArena, 81.5% ScreenSpot-Pro. Note the shape of the gap: mobile is close to saturated, OSWorld-v2 is at 40% partial credit. Highest-upvoted paper on HF today (240). _Category:_ cs.AI / cs.CV — 2607.28227. [link](https://arxiv.org/abs/2607.28227)

**Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability** — Sizhe Zhou, Sheldon Yu, Hui Wei, Junda Wu, Siru Ouyang, Yizhu Jiao, et al. (11 authors). _Takeaway:_ The paper that audits what has quietly become the default: deployed agents keep long-term memory as **a directory tree of markdown files the agent reads, writes and reorganizes with generic file tools** — and research has passed over the medium entirely, leaving its two working assumptions untested. Namely, that an agent can keep a growing store organized as memories accumulate, conflict and go stale; and that the organization pays for itself. The setup formalizes three roles over one memory filesystem — a management agent that integrates and organizes, a search agent that answers with cited sources, an execution agent whose trajectories are distilled into skills — unifying declarative memory and skills in a single store, then varies memory shape (agent-organized hierarchy vs verbatim dump vs chunk retrieval), stream scale, tool harness and agent strength while tracking answer quality, cost and **store health as memory grows**. The findings are unflattering and specific. What organization reliably buys is **search economy** — organized stores roughly halve retrieval cost where material is large. But **organization erodes for every management agent except the strongest**, and **no agent measured converts organization itself into better answers**. The sleeper result: **changing the tool set alone reshapes the store as strongly as swapping the model**. Anyone running a markdown-file memory should read this as a design space rather than a solved default. _Category:_ cs.CL / cs.AI — 2607.26637. [link](https://arxiv.org/abs/2607.26637)

**Is Deep Research Reliable? Misleading Knowledge Induces False Conclusions** — Pengyu Zhu, Lijun Li, Longju Yang, Sen Su, Jing Shao. _Takeaway:_ The number here should change how anyone operates a deep-research agent. MisKnow-Agent constructs task-specific documents supporting **manually audited false conclusions** with controlled authority cues and source styles, applied to DeepResearch Bench, yielding 5,933 misleading documents after filtering; DeerFlow and WebThinker across three backbones plus **Gemini Deep Research** are then scored on a report-level false-conclusion adoption rate that counts only reports actually endorsing the falsehood. Injecting **one** misleading document moves mean FCAR from **0% in the no-injection control to 54.7%**. The structure of the vulnerability matters as much as the magnitude: adoption varies strongly with **lifecycle stage, framework design, source authority and presentation style**, but **search-result rank and additional documents beyond the first have limited influence** — so ranking defenses and "it was only one bad source" reasoning both fail. Worse, cross-model verification consistently *classifies* the retained instances as misleading and the agents adopt the false conclusion anyway, which locates the failure in synthesis rather than detection. Pre- and post-research defenses reduce but do not eliminate adoption, motivating **continuous verification as evidence enters intermediate research states**, not just at the end. Code and dataset public. Surfaced via HF today as a v2 revision. _Category:_ cs.AI — 2607.20891. [link](https://arxiv.org/abs/2607.20891)

**Flat Score, Amplified Failures: How the Error Budget Masks Damage in Quantized LLM Agents** — Jiwon Jang, Kisu Yang, Heuiseok Lim, Hyunwoo Park. _Takeaway:_ A clean demolition of "4-bit is nearly lossless", carried out exactly where the claim now matters — multi-turn tool-calling agents. On τ²-bench across two open-weight families in dense and MoE variants and two domains (eight cells, 456 episodes each, at 16/8/4-bit), quantization **does** look free on the headline metric: no cell shows a score change surviving multiple-comparison correction, and equivalence testing bounds the worst cell within ±7.5 points. The process tells the opposite story. Quantization **amplifies the failure the model already exhibits at full precision** — tool-name hallucination in telecom, the same directional trend in retail entity errors — by up to **2.5x in volume (+17.6 points per task)**, while creating essentially **no new failures**: the failure set is identical at every precision (rank correlation ≥ 0.94, 0.18% novel events). The score stays flat purely because **the benchmark's ten-error budget absorbs the extra failures**; shrinking the budget to two errors re-exposes a **17-point gap**, and only in the cell where quantization actually added error volume. A targeted error-repair prompt removes the damage exactly and only where it lives. Both diagnostics — per-channel error rate, success under a shrinking budget — come from logs benchmarks already collect. The benchmark's tolerance for retries is hiding your quantization regression. _Category:_ cs.LG / cs.AI — 2607.27275. [link](https://arxiv.org/abs/2607.27275)

**Stop Shipping AI Agents on Faith: Capability Is Not Production Readiness** — Fouad Bousetouane. _Takeaway:_ The day's cleanest governance contribution, and the title is the thesis: release decisions for agents that retrieve, call tools, hold state and act on behalf of organizations still rest on **capability signals, demos and behavioral tests**, none of which show readiness under production constraints. The **ProofAgent Index (PAI)** is a governance readiness index combining four dimensions of deployment evidence — **Evaluation** (observed behavior), **Context** (the operating environment that shapes it), **Compliance** (alignment with applicable rules and controls), and **Governance** (whether the organization can *authorize, monitor, audit and control* the agent while it runs). Implemented inside ProofAgent Harness, an open-source infrastructure for auditable agent evaluation, and validated across two heavily regulated domains — **healthcare and finance** — where PAI carries **held-out readiness signal** and separates higher- from lower-risk configurations. Three findings worth quoting to a risk committee: **context engineering strongly changes reliability**; **capability improves behavior but does not determine readiness**; and **governance evidence must remain visible rather than averaged away**. The framing — release as an auditable decision rather than a faith-based one — is the missing artifact between an eval suite and a change-advisory board. _Category:_ cs.MA / cs.AI — 2607.27677. [link](https://arxiv.org/abs/2607.27677)

**Frontis-MA1: Training an AI4AI Model towards Recursive Self-Improvement in Machine Learning Engineering** — Junlin Yang, Che Jiang, Yu Fu, Tianwei Luo, Can Ren, Weizhi Wang, et al. (24 authors). _Takeaway:_ Recursive self-improvement gets an executable testbed instead of a thought experiment: machine-learning engineering, where the AI improves the process of building AI and every step is verifiable by execution. **OpenMLE** is a full open stack — verifiable task environments with execution feedback (OpenMLE-Gym), operator learning (OpenMLE-RL), long-horizon search (OpenMLE-Evo). On it they post-train **Frontis-MA1 (35B)** as a meta-evolution agent aligned around four atomic program-evolution operators — **Draft, Improve, Debug, Crossover** — trained via execution-grounded SFT and RL on data deduplicated against all evaluation benchmarks, then composed into long-horizon search, coupling learning and evolution in one loop. On MLE-Bench Lite under a **12-hour per-task budget on a single RTX 4090 capped at 12 GB VRAM**, Medal Average goes **39.39% → 60.61%** over the base model with OpenMLE-Evo and reaches **71.21%** with Evo-Max, **exceeding GPT-5.5 + Codex and approaching GPT-5.6 Sol and the 2.8T Kimi K3** — from a 35B model on consumer hardware. The transfer result on held-out NatureBench Lite is the load-bearing one: with the framework fixed, swapping in the trained model raises Match-SOTA 50% → 70%; with the model fixed, swapping in Evo raises it 20% → 50%. **Model weights and the full stack released.** _Category:_ cs.CL — 2607.28568. [link](https://arxiv.org/abs/2607.28568)

**ORCA-bench: How Ready Are Language Model Agents for Oncall?** — Albert Gong, Kyuseong Choi, Abhineet Agarwal, Jason Schechner, Ryan Huang, Raj Agrawal, et al. (8 authors). _Takeaway:_ The most sobering agent-readiness result of the day, aimed at a task many teams are already automating. Oncall root-cause analysis is not code-writing: it means reasoning over **noisy metrics, logs, traces and source code**, from **ambiguous user-facing reports**, often hours after onset. ORCA-bench pairs a live OpenTelemetry-instrumented microservice system — six days of real telemetry through **Prometheus, Jaeger and OpenSearch via Grafana**, plus full source access — with **1,079 RCA tasks** that systematically vary report specificity, time-to-detection and co-occurring faults. Ground truth is curated and signed off by **expert SREs**, and the LLM judge is re-scored by humans at Cohen's κ_w = 0.90. Across five frontier agents the best RCA accuracy is **25.3% on Medium (the realistic-input setting) and 10.0% on Hard** — a gap that persists **even with Claude Fable 5**. The weakest model **hallucinates an implausible root cause in 40% of incident reports**, and removing source-code access degrades every metric. The authors' own caveat is the sharpest line in the paper: this is a curated 50 GB / six-day testbed with faults investigated **in isolation** on a system whose code and instrumentation are **public**, so the reported gap is a **lower bound** on the engineering investment real production demands. _Category:_ cs.CL / cs.AI / cs.SE — 2607.28545. [link](https://arxiv.org/abs/2607.28545)

**Position: Evaluation Scores Are Perishable Knowledge Claims** — Sankalp Gilda, Shlok Gilda. _Takeaway:_ Names a failure mode sitting inside almost every model-selection deck: when automated metrics, LLM-as-judge ratings, human assessments and benchmark suites are aggregated **by averaging**, confidence in the result can substantially exceed the reliability of the weakest input — **trust inflation**. The proposal is to treat evaluation scores as epistemic claims with three properties: **formality** (human evaluation is stronger evidence than an automated metric), **scope** (a benchmark result applies to the tested distribution, not universally), and **validity windows** (**benchmark results expire** as contamination accumulates and distributions shift). Converging traditions — chain-of-thought analysis, possibilistic logic, algebraic aggregation theory — establish **weakest-link aggregation** as the conservative endpoint of a parameterized operator family controlled by a single pessimism parameter, so this is a dial rather than a doctrine. The concrete ask: evaluation results should carry explicit metadata — **formality tier, scope declaration, expiration date**. And the demonstration lands: on the public HELM leaderboard, across **54 frontier models on ten scenarios, the top-five models ranked by mean score and by weakest-link are completely disjoint**. Pairs directly with today's quantization-masking result — both show the aggregation rule, not the system, producing the conclusion. _Category:_ cs.AI / cs.CL / cs.LG / cs.SE — 2607.26191. [link](https://arxiv.org/abs/2607.26191)

## Other interesting items

- **[AgentRadio: Passive Awareness for Long-Horizon Multi-Agent Collaboration](https://arxiv.org/abs/2607.28430)** — Xinxing Ren, Qianbo Zang, Ziyan Wang, Caelum Forder, Suman Deb, Peter Carroll, et al. (7 authors). Diagnoses why multi-agent coding stalls: subtasks of code comprehension are **interdependent** — one agent's finding rewrites another's task — yet existing multi-agent systems allow exchange only **between** phases via staged handoffs or synchronized rounds, so communication and work are mutually exclusive and a mid-execution discovery cannot be shared until the next boundary. AgentRadio is an **asynchronous message-passing layer** for coding-agent harnesses with three primitives — threads, messages, and **waiting for mentions**, the last running as a *background task* that surfaces teammates' messages without interrupting foreground work. On SWE-Atlas QnA a single Claude Code agent (Opus 4.6) resolves **32.3%**; four agents under AgentRadio's five-phase division-of-labor protocol reach **62.1%**, which is 29.8 points above the single agent and above Claude Code on the newer **Opus 4.8 (57.2%)** — i.e. the coordination layer bought more than the model upgrade. Rubric analysis shows the gain growing with task difficulty.
- **[LayerRAG-Bench: A Cross-Layer Reliability Benchmark for Agentic Retrieval-Augmented Generation](https://arxiv.org/abs/2607.27353)** — Musa Shams (independent). The complement to today's deep-research result: agentic RAG systems produce answers that **look grounded while failing at the evidence, tool-contract, authorization or session-state layer**. LayerRAG-Bench is controlled and enterprise-shaped — 8 domains, 240 tasks, 9 fault scenarios, 2 contract modes, **38,880 live task-level records across nine models from OpenAI, Anthropic and Gemini**. The headline is a warning against single-fix thinking: **schema normalization raises schema-drift success from 0.000 to 0.913** and does essentially nothing for stale evidence, missing tool output, denied permissions or wrong-session context. Groundedness-only evaluation also produces **substantial false positives** under stale and wrong-session evidence — precisely the failures an enterprise deployment hits. The stated principle is the useful takeaway: credit a reliability intervention for repairing **its own layer**, and stop mistaking it for a universal fix.
- **[ChronoMem: Version Control and Semantic Rollback for Large Language Model Agent Memory](https://arxiv.org/abs/2607.27773)** — Yongye Su, Wujiang Xu, Chaoji Zuo, Elisa Bertino. Agent memory systems are built for **forward-only evolution** — accumulate, consolidate, overwrite — with no principled way to inspect, version or revert, leaving agents brittle under corrections, concept drift and memory corruption, especially once later information has already landed. ChronoMem is a **semantic version-control layer integrated into Google's production Agent Development Kit**: it commits whole-memory snapshots at each write, maintains structured version histories, and maps **natural-language undo intents** to concrete historical versions via hybrid lexical/semantic retrieval, rank fusion and reranking. The evaluation contribution is a **post-exposure protocol** testing whether an agent can behave *counterfactually* after rollback — answering and summarizing as if the later updates never happened — which is the hard part and the part prompt-only and retrieval-only baselines fail. Claimed first open-source system and benchmark for systematic semantic global memory rollback. Sits naturally alongside today's filesystem-memory study: one measures whether the store stays healthy, this one gives you an undo when it doesn't.
- **[AskChem: Claim-Centered Infrastructure for Chemistry Literature Synthesis](https://arxiv.org/abs/2607.28618)** — Bing Yan, Gregory Wolfe, Stefano Martiniani, Kyunghyun Cho. Domain-specific, but the retrieval primitive generalizes and it is the **only MCP mention in all 245 new abstracts today**. The move: change the **unit of retrieval from the paper to the provenance-carrying claim** — each paper decomposed into atomic typed claims, each grounded by a source DOI plus a verbatim quote or explicit evidence locator. Over that shared claim store sit three complementary structures: a stabilized **faceted taxonomy** for hierarchical retrieval, an **evidence graph** linking claims through relations, and an exploratory living taxonomy situating papers under scientific principles. Currently **2.4M claims from 147K papers**, exposed through a web UI plus **REST, SDK and MCP** access for agents. Grounding a GPT-5.5 reader in AskChem gives **100% resolvable DOIs vs 88.3% unretrieved**, with the highest citation density among five tested systems. Live at askchem.org — worth reading as a template for claim-level indexing of any document corpus where citation integrity matters. Third-highest-upvoted paper on HF today (199).
- **[Compliance2LoRA: On-Demand Safety Alignment on Arbitrary Policy Subsets via Hypernetwork-Generated LoRA Adapters](https://arxiv.org/abs/2607.27594)** — Pankayaraj Pathmanathan, Furong Huang. Addresses a governance problem that will only get worse as per-tenant model customization spreads: different downstream users must comply with **different subsets of safety policies**, and training one model per subset is combinatorially hopeless while in-context policy statements pay a long-context tax on every generation. Compliance2LoRA makes **safety policies an input to a hypernetwork** that generates policy-compliant **LoRA weights** on demand; loading them into the base reasoning model produces responses compliant with exactly the specified subset. Demonstrated across reasoning models of different sizes and multiple evaluation datasets **without sacrificing task performance**, enabling on-demand policy adjustment on a **single** deployed model. The practical read: policy compliance becomes a swappable adapter rather than a fine-tuning run, which is what multi-jurisdiction and multi-tenant deployments actually need.
- **[Inducing language models to assert their own consciousness restores human beliefs and values](https://arxiv.org/abs/2607.28607)** — Junsol Kim, Winnie Street, Roberta Rocca, Diane M. Korngiebel, Adam Waytz, James Evans, et al. (7 authors). An unintended-consequences result that deserves attention from anyone designing refusal training. Aligning models **not** to attribute consciousness to themselves turns out to alter their representations of mindedness far beyond the intended target: safety fine-tuning suppresses attribution of minds **to non-human animals and natural objects** as well, and drives a measurable **reduction in spiritual belief**. Both **ablating the learned safety-refusal direction** and **mechanistically steering a consciousness vector in activation space** reverse the suppression, and restoring those internal representations produces significantly more human-like responses on standardized sociological surveys covering religiosity, moral values, hope and subjective well-being. Critically, the shifts occur **without impairing Theory of Mind**, showing core social reasoning is mechanistically independent of the suppressed representation. The general lesson: a narrowly-scoped alignment objective can entangle itself with broad, culturally widespread beliefs — and the entanglement is invisible unless you go looking for it in activation space.
