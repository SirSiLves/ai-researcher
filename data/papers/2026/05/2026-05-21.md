# AI Papers — 2026-05-21

_Collector: ai-papers. Slice: ArXiv (cs.CL, cs.AI, cs.LG, cs.MA, stat.ML, cs.IR), HF Papers, papers.cool._

## Top picks

- **Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory** — authors n/a. _Takeaway:_ Argues that atomic-fact memory stores collapse under long-horizon use; proposes a structured, compositional memory representation that preserves provenance and relational context for lifelong agents. _Category:_ arXiv 2605.19952. [link](https://arxiv.org/abs/2605.19952)

- **Code as Agent Harness** — authors n/a. _Takeaway:_ Treats generated code as the orchestration substrate for LLM agents, replacing JSON tool-call plumbing with executable programs that drive tool use. _Category:_ arXiv 2605.18747. [link](https://arxiv.org/abs/2605.18747)

- **Predictive Maps of Multi-Agent Reasoning: A Successor-Representation Spectrum for LLM Communication Topologies** — authors n/a. _Takeaway:_ Borrows the successor-representation idea from RL to predict, ahead of time, which communication topology a multi-agent LLM team should adopt — no post-hoc topology sweeps. _Category:_ arXiv 2605.11453. [link](https://arxiv.org/abs/2605.11453)

- **AgentRx: A Benchmark Study of LLM Agents for Multimodal Clinical Prediction Tasks** — authors n/a. _Takeaway:_ Multimodal clinical-prediction benchmark for LLM agents — pushes agent evaluation beyond text-only sandboxes into mixed image/text/tabular medical workflows. _Category:_ arXiv 2605.10286. [link](https://arxiv.org/abs/2605.10286v1)

- **Iterative Audit Convergence in LLM-Managed Multi-Agent Systems** — authors n/a. _Takeaway:_ Case study in QA for prompt engineering where an LLM auditor agent converges on a stable verdict across iterations — useful primitive for self-checking multi-agent pipelines. _Category:_ arXiv 2605.12280. [link](https://arxiv.org/abs/2605.12280)

- **Beyond Accuracy: Policy Invariance as a Reliability Test for LLM Safety Judges** — authors n/a. _Takeaway:_ Reliability of LLM-as-judge for safety is mis-measured by accuracy alone; introduces a policy-invariance test that flags judges whose verdicts swing under benign rephrasings of the safety policy. _Category:_ arXiv 2605.06161. [link](https://arxiv.org/abs/2605.06161)

- **MARLIN: Multi-Agent Game-Theoretic Reinforcement Learning for Sustainable LLM Inference in Cloud Datacenters** — authors n/a. _Takeaway:_ Multi-agent RL framework that co-optimizes latency, cost, and carbon for LLM serving — relevant for platform/operations teams sizing inference fleets. _Category:_ arXiv 2605.13496. [link](https://arxiv.org/abs/2605.13496)

- **VibeServe: Can AI Agents Build Bespoke LLM Serving Systems?** — authors n/a. _Takeaway:_ Tests whether LLM agents can synthesize end-to-end serving stacks per workload; early evidence that agent-generated serving configs beat generic defaults on tail latency and cost. _Category:_ arXiv 2605.06068. [link](https://arxiv.org/abs/2605.06068)

- **AJAR: Adaptive Jailbreak Architecture for Red-teaming** — authors n/a. _Takeaway:_ Holistic red-teaming framework that targets LLM-based agents (not just chat models) — covers persistent state, tool access, and autonomous control loops where most current jailbreak benchmarks don't reach. _Category:_ arXiv 2601.10971. [link](https://arxiv.org/abs/2601.10971)

- **A Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP** — authors n/a. _Takeaway:_ Side-by-side comparison of the four leading agent-communication protocols (Model Context Protocol, Agent Communication Protocol, Agent-to-Agent, Agent Network Protocol) with deployment-context trade-offs — useful reference when picking an agent runtime substrate. _Category:_ arXiv 2505.02279. [link](https://arxiv.org/abs/2505.02279)

## Other interesting items

- **[The Evolution of Tool Use in LLM Agents: From Single-Tool Call to Multi-Tool Orchestration](https://arxiv.org/abs/2603.22862)** — Organizes the tool-use literature along six axes (planning, training, safety, efficiency, capability completeness, benchmarks); useful map for agent-platform decisions.
- **[Utility-Guided Agent Orchestration for Efficient LLM Tool Use](https://arxiv.org/abs/2603.19896)** — Orchestration policy that picks among respond / retrieve / tool-call / verify / stop by balancing estimated gain, step cost, uncertainty, and redundancy.
- **[Breaking the Curse of Dimensionality: On the Stability of Modern Vector Retrieval](https://arxiv.org/abs/2512.12458)** — Stability analysis of high-dimensional dense retrieval; complements last week's "Black-Hole Attack" paper on vector-DB fragility.
- **[Benchmarking Filtered Approximate Nearest Neighbor Search on Transformer Embeddings](https://arxiv.org/abs/2507.21989)** — New 2.7M-paper benchmark (`arxiv-for-fanns`) covering eleven FANNS methods across filter types and scales; concrete baseline for vector-DB selection.
- **[Jailbreak-as-a-Service++: Distributed AI-Driven Malicious Information Campaigns Powered by LLM Crowdsourcing](https://arxiv.org/abs/2505.21184)** — Frames coordinated misuse across MaaS ecosystems; argues current per-provider safeguards miss ecosystem-level threats.
