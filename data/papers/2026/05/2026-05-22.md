# AI Papers — 2026-05-22

_Collector: ai-papers. Slice: ArXiv (cs.CL, cs.AI, cs.LG, cs.MA, stat.ML, cs.IR), HF Papers, papers.cool._

## Top picks

- **EngiAI: A Multi-Agent Framework and Benchmark Suite for LLM-Driven Engineering Design** — authors n/a. _Takeaway:_ Multi-agent framework plus benchmark that takes LLM agents beyond chat/code into engineering-design workflows; standardizes evaluation across decomposition, constraint checking, and artifact generation. _Category:_ arXiv 2605.19743. [link](https://arxiv.org/abs/2605.19743)

- **Cattle Trade: A Multi-Agent Benchmark for LLM Bluffing, Bidding, and Bargaining** — authors n/a. _Takeaway:_ Strategic-reasoning benchmark with imperfect information — combines auctions, trade, bargaining, and bluffing in a single environment; complements the existing economic-agent benches by adding adversarial deception. _Category:_ arXiv 2605.14537. [link](https://arxiv.org/abs/2605.14537)

- **Towards Dependable Retrieval-Augmented Generation Using Factual Confidence Prediction** — authors n/a. _Takeaway:_ Trains a confidence predictor over RAG outputs so the system can abstain or escalate when factual grounding is weak; a deployable primitive for high-stakes RAG. _Category:_ arXiv 2605.05244. [link](https://arxiv.org/abs/2605.05244)

- **MCJudgeBench: A Benchmark for Constraint-Level Judge Evaluation in Multi-Constraint Instruction Following** — authors n/a. _Takeaway:_ Pushes LLM-as-judge evaluation from "did it follow the instruction" to per-constraint verdicts on multi-constraint prompts — exposes that current judges are weakest exactly where production prompts live. _Category:_ arXiv 2605.03858. [link](https://arxiv.org/abs/2605.03858)

- **Towards Reliable LLM Evaluation: Correcting the Winner's Curse in Adaptive Benchmarking** — authors n/a. _Takeaway:_ Shows adaptive prompt/program search inflates reported scores via a winner's-curse effect; proposes a correction so leaderboard numbers track fresh-data performance. _Category:_ arXiv 2605.05973. [link](https://arxiv.org/abs/2605.05973)

- **Enhanced LLM Reasoning by Optimizing Reward Functions with Search-Driven Reinforcement Learning** — authors n/a. _Takeaway:_ Search-driven RL over the reward function itself (not just the policy) — closes a gap where RLHF reward shaping is usually hand-tuned. Practical implications for post-training pipelines. _Category:_ arXiv 2605.02073. [link](https://arxiv.org/abs/2605.02073)

- **Towards the Next Frontier of LLMs, Training on Private Data: A Cross-Domain Benchmark for Federated Fine-Tuning** — authors n/a. _Takeaway:_ Cross-domain (healthcare/finance) benchmark for federated fine-tuning of LLMs; concrete reference for enterprises that can't ship data to a central trainer. _Category:_ arXiv 2605.13936. [link](https://arxiv.org/abs/2605.13936)

- **MARLIN: Multi-Agent Game-Theoretic Reinforcement Learning for Sustainable LLM Inference in Cloud Datacenters** — authors n/a. _Takeaway:_ Multi-agent RL co-optimizing latency, cost, and carbon for LLM serving; relevant for platform/operations teams that need to defend cost-per-token economics. (Re-surfaced from yesterday's index due to fresh citations in serving-systems literature.) _Category:_ arXiv 2605.13496. [link](https://arxiv.org/abs/2605.13496)

- **Reinforcement Learning for LLM-based Multi-Agent Systems through Orchestration Traces** — authors n/a. _Takeaway:_ Uses recorded orchestration traces as the training signal for RL over multi-agent systems — sidesteps the lack of well-defined per-step rewards in agent workflows. _Category:_ arXiv 2605.02801. [link](https://arxiv.org/abs/2605.02801)

- **MCP Tool Descriptions Are Smelly! Towards Improving AI Agent Efficiency with Augmented MCP Tool Descriptions** — authors n/a. _Takeaway:_ Empirical study showing real-world MCP tool descriptions exhibit "code-smell"-like quality problems that hurt agent tool selection; proposes augmentation heuristics that lift downstream task success. _Category:_ arXiv 2602.14878. [link](https://arxiv.org/abs/2602.14878)

## Other interesting items

- **[Iterative Audit Convergence in LLM-Managed Multi-Agent Systems: A Case Study in Prompt Engineering Quality Assurance](https://arxiv.org/abs/2605.12280)** — Earlier-week paper picking up citations; useful self-checking primitive for multi-agent pipelines.
- **[Dynamic Attentional Context Scoping for Agent-Triggered Focus Sessions in Multi-Agent LLM Orchestration](https://arxiv.org/list/cs.MA/current)** — Attention-scoping mechanism that lets a coordinator agent allocate context budget per sub-agent on demand.
- **[CASPIAN: Online Detection and Attribution of Cascade Attacks in LLM Multi-Agent Systems](https://arxiv.org/list/cs.MA/current)** — Online detector that flags and attributes cascade attacks across agent chains — addresses a class of threats that don't appear in single-model jailbreak benches.
- **[Mathematical Reasoning in Large Language Models: Benchmarks, Architectures, Evaluation, and Open Challenges](https://arxiv.org/abs/2605.19723)** — Survey but synthesizes evaluation-protocol problems (contamination, prompt-fragility) usefully; worth skimming for benchmark hygiene.
- **[Breaking the Protocol: Security Analysis of the Model Context Protocol Specification and Prompt Injection Vulnerabilities in Tool-Integrated LLM Agents](https://arxiv.org/abs/2601.17549)** — Picks apart MCP's threat surface; complements yesterday's interop-survey pick with concrete attack classes.
