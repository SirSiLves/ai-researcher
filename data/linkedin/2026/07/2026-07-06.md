## Pulse / long-form articles (priority layer)

**Microsoft and MCP: How the Ecosystem Is Embracing the Model Context Protocol** — Marcel Broschk (lang: en). Surveys Microsoft's full-stack MCP adoption across VS Code, GitHub Copilot, Azure AI Foundry, Semantic Kernel and M365 Copilot (Work IQ), framing MCP as the de-facto AI-to-tool standard with OAuth 2.0 auth and API Management governance. _Why interesting:_ concrete, vendor-by-vendor map of how MCP became enterprise infrastructure — useful grounding for the MCP focus area. [https://www.linkedin.com/pulse/microsoft-mcp-how-ecosystem-embracing-model-context-protocol-broschk-5mexe](https://www.linkedin.com/pulse/microsoft-mcp-how-ecosystem-embracing-model-context-protocol-broschk-5mexe)

**Next-Gen Agentic Security Needs Next-Gen Controls** — Yuri Livshitz (lang: en). Argues AI security is migrating from deterministic choke-points (gateways, MCP gateway, egress proxy) toward model-internal judgment and "agents governing agents" as single-agent setups give way to A2A meshes; keeps irreversible actions (money, egress, deletion) behind hard gates and pushes control into the identity fabric. Cites EchoLeak (CVE-2025-32711), DeepMind CaMeL, and A2A v1.0 under the Linux Foundation. _Why interesting:_ the sharpest current take on where agentic-security controls should live as MCP+A2A becomes the default stack. [https://www.linkedin.com/pulse/next-gen-agentic-security-needs-controls-yuri-livshitz-4ch2f](https://www.linkedin.com/pulse/next-gen-agentic-security-needs-controls-yuri-livshitz-4ch2f)

**Agents Deserve Their Own Transport, and AGTP Refuses to Pretend Otherwise** — Chris Hood (lang: en). Makes the case that agents are a new class of network participant (absent owner, delegated authority, machine-speed fan-out, attribution outliving the request) and that HTTP — built for a human at a browser — is the wrong substrate; proposes AGTP as a "narrow-waist" transport with MCP and A2A riding on top as tenants rather than rivals. _Why interesting:_ a genuinely contrarian contribution to the agent-interoperability-protocol debate, arguing one layer below MCP/A2A. [https://www.linkedin.com/pulse/agents-deserve-own-transport-agtp-refuses-pretend-otherwise-hood-cexjc](https://www.linkedin.com/pulse/agents-deserve-own-transport-agtp-refuses-pretend-otherwise-hood-cexjc)

**Why RAG is Failing: The Shift from Retrieval to AI Reasoning** — Mirko Peters (lang: en). Contends enterprise RAG hits a "latency wall" on "liquid" real-time context (who's working on what now, live permissions, in-flight decisions) versus static documents, and ties the fix to reasoning-over-live-signals plus per-agent identity (Entra Agent IDs / Agent 365) instead of shared service accounts, enabling governed A2A workflows. _Why interesting:_ frames the retrieval-vs-reasoning debate and the agent-identity/governance angle together; Microsoft-Copilot-flavored but a real argument. [https://www.linkedin.com/pulse/why-rag-failing-shift-from-retrieval-ai-reasoning-mirko-peters-bbtle](https://www.linkedin.com/pulse/why-rag-failing-shift-from-retrieval-ai-reasoning-mirko-peters-bbtle)

**ISO 42001 and the EU AI Act: They're Not Competing. They Never Were.** — Fernando Moreno Alvarez (lang: en). Distinguishes the EU AI Act (a legal instrument governing specific high-risk systems) from ISO 42001 (an organization-wide AI management-system standard, ISO 27001-style), argues they are complementary — "one sets the bar, the other builds the program that clears it" — and recommends doing ISO 42001 first or in parallel so Act-conformity evidence already exists. _Why interesting:_ practical governance sequencing advice that cuts through the common "pick one" confusion. [https://www.linkedin.com/pulse/iso-42001-eu-ai-act-theyre-competing-never-were-fernando-23xge](https://www.linkedin.com/pulse/iso-42001-eu-ai-act-theyre-competing-never-were-fernando-23xge)
