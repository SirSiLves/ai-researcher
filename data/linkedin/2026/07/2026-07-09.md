## Pulse / long-form articles (priority layer)

**Threat Modeling the Model Context Protocol** — Brett Crawley (en). Argues the top real-world MCP risk is mundane credential/token exposure, not exotic prompt injection, and that "AI guardrails" (classifiers, LLM-judges) are probabilistic and therefore not security controls. Core thesis: bound impact with deterministic boundaries first (per-user/per-purpose credentials, egress allow-lists, taint-flow denial), then layer probabilistic guardrails on top — never instead. Walks STRIDE threat classes, the "lethal trifecta," and two real exploits (GitHub MCP toxic-flow, EchoLeak/CVE-2025-32711). _Why interesting:_ the sharpest practitioner treatment yet of why MCP security must be per-deployment and deterministic. [https://www.linkedin.com/pulse/threat-modeling-model-context-protocol-brett-crawley-pmbff]

**The State of Agentic AI Standards in 2026: MCP, A2A, WebMCP, OSI, and the Protocol Stack Taking Shape** — Alex Merced (en). A comprehensive mid-2026 map of the agent protocol stack, layer by layer: MCP (tool layer, "won"), A2A (now at 1.0 under Linux Foundation with signed Agent Cards, 150+ prod orgs), WebMCP (Chrome Canary preview, W3C track), OSI/semantic layer, and the crowded payments layer (AP2, ACP, x402). Includes a worked example tracing one business request through all layers. _Why interesting:_ single best reference for how the protocols layer rather than compete, with honest status (shipped/versioned/previewed/aspirational) per layer. [https://www.linkedin.com/pulse/state-agentic-ai-standards-2026-mcp-a2a-webmcp-osi-protocol-merced-uhxxe]

**Why "Human In the Loop" Is Agentic Governance Theater** — Stephen Schmidt / Amazon CSO (en). Argues human approval loops collapse into rubber-stamping at agent scale and are not governance. Prescribes: behavioral eval + adversarial testing + continuous monitoring on every model/tool change; deterministic infrastructure-level controls outside the agent (not in the prompt); earned autonomy (shadow mode → independence); and a named-human owner with immutable audit logs per outcome. Concrete Amazon data: 26,000 internal agents, 360k+ auths/week, a compliance screener over 2.5B transactions/day now 60%+ automated at 96% accuracy. _Why interesting:_ hard operational numbers behind the "set boundaries outside the agent" argument. [https://www.linkedin.com/pulse/why-human-loop-agentic-governance-theater-stephen-schmidt-8dcde]

**Schunk-Pionierin Hermle, OpenAIs Jalapeño-Chip und die Schweizer Souveränitätsfrage** — Andy Huber (de). Swiss/German weekly digest with four threads: (1) how Schunk (80-yr precision-engineering firm) built Schunk-GPT on Azure and drove adoption by giving skeptics safety, not pressure; (2) OpenAI's first custom inference chip "Jalapeño" (with Broadcom, 9-month tape-out) as a signal that compute is now a strategic raw material; (3) EPFL AI Center's Marcel Salathé asking at the Swiss Telecommunication Summit whether Switzerland can still afford intelligence — sovereignty is about infrastructure, not just law; (4) an ETH KOF study finding unemployment in AI-exposed Swiss jobs rose up to 27% more since ChatGPT. _Why interesting:_ concrete Swiss-market angle (EPFL, ETH KOF, Phoenix Technologies hardware-stop) the user cares about, plus the SAP/Google/Microsoft agent-governance race framed for Swiss firms. [https://www.linkedin.com/pulse/schunk-pionierin-hermle-openais-jalape%C3%B1o-chip-und-die-andy-huber-w1dve]

**Designing a Governed MCP Platform for Medium-Scale Enterprise AI** — Biren Patel (en). Reference architecture for ~100 tools / 25 agents / 100k users: all agent-to-tool traffic passes through an MCP Gateway (policy enforcement point); control plane (tool registry, policy, metadata, audit) separated from data plane (domain MCP servers owned by teams); capability-based governance ("Read Customer Data") over per-tool ACLs for scalability; tool-owning team stays the access authority. Frames MCP governance as the next "API management for microservices." _Why interesting:_ concrete, scale-bounded enterprise blueprint rather than abstract MCP advocacy. [https://www.linkedin.com/pulse/designing-governed-mcp-platform-medium-scale-enterprise-biren-patel-3kmcf]

**Beyond Basic RAG: 3 Advanced Retrieval Techniques Every AI Engineer Should Know** — Abhishek Chopra (en). Practitioner walkthrough of hybrid search (vector + BM25 for exact identifiers), re-ranking (20→5 docs before the LLM, cutting hallucinations and token use), and GraphRAG (retrieving relationships/entities for multi-hop questions), illustrated with a hotel-concierge example. Argues retrieval engineering now matters as much as prompt engineering — the LLM sits at the end of the pipeline. _Why interesting:_ clean, concrete framing of why retrieval quality beats bigger models for enterprise RAG. [https://www.linkedin.com/pulse/beyond-basic-rag-3-advanced-retrieval-techniques-every-chopra-sy43f]

**The Agent Market Is Confusing Because Every Layer Is Being Sold as the Same Thing** — Zynd (en; note: light vendor framing). Disambiguates the agent stack by job: models (reasoning), frameworks (LangGraph/CrewAI — internal workflow), MCP (tool/data connectivity), A2A (cross-vendor agent communication), x402 (in-request micropayments), and registries/networks (discovery, identity, trust). Uses a sales-research agent to show one product touches several layers, and warns builders to ask "what job does this solve?" before adopting a protocol. _Why interesting:_ useful counter to the "MCP vs A2A vs x402" confusion; the layer map holds despite the Zynd pitch at the end. [https://www.linkedin.com/pulse/agent-market-confusing-because-every-layer-being-sold-same-thing-de1ec]

**EU AI Act vs ISO 42001: Where They Overlap, Where They Differ** — Tijana Zunic Maric (en; note: vendor pitch woven in). Compares the binding EU AI Act (4 risk tiers, extraterritorial, fines up to EUR 35M / 7% turnover) with voluntary ISO/IEC 42001 (AIMS, Plan-Do-Check-Act, third-party cert, no penalties). Estimates ~40–50% overlap in high-level requirements (risk management, data governance, documentation, transparency, monitoring) but stresses ISO 42001 alone does not cover EU-specific obligations (conformity assessment, CE marking, registration, prohibited practices). Recommends implementing both, ISO first as the operational backbone. _Why interesting:_ clear overlap/gap breakdown for teams facing both regimes; discount the Whisperly product sections. [https://www.linkedin.com/pulse/eu-ai-act-vs-iso-42001-where-overlap-differ-tijana-zunic-maric-rqcef]
