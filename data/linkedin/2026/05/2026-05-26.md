- **The Next Enterprise Battle: Governing AI Agents Inside Operational Workflows** — Eduardo Poggi (en).
  Reads the market shift from "smartest model" to "who controls the cognitive operational layer of the enterprise" — Microsoft 365 copilots, Salesforce Agentforce, SAP Joule, ServiceNow AI agents and Anthropic's small-business prebuilt workflows are converging on operational outcomes, not benchmark scores. Traditional DLP/IAM/PAM/CASB/Zero-Trust were designed to govern access to information; agentic AI changes the question to which actions and decisions autonomous agents can execute. Predicts the next platform-architecture layer: agent identity management, runtime authorization, operational permission governance, execution observability, decision tracing, policy enforcement, lifecycle management and runtime supervision.
  _Why interesting:_ A clean framing of the agentic governance gap that pairs directly with Priore's MCP-governance argument from yesterday — same problem, top-down strategy lens vs bottom-up legal lens.

- **#22: DeepDive — ACP vs MCP vs A2A: The Complete Guide to AI Agent Protocols** — NeosAlpha Technologies (en).
  Maps the three-layer agent protocol stack with explicit "what problem does each solve" framing: MCP (Anthropic, 2024, agent-to-tool, 97M monthly downloads, production-ready), A2A (Google, cross-vendor agent coordination, v0.3 with limited production), and ACP (IBM Research, REST-native peer messaging within enterprise environments, early-stage). Cites Gartner's 40% enterprise-application AI-agent forecast for 2026 and Accenture's "6× revenue growth for interoperable companies." Three concrete enterprise examples (order-to-cash, SOC automation, financial reporting) showing all three protocols layered together. Honest about challenges: protocol maturity mismatch, A2A's new attack surfaces (Agent Card spoofing, task injection), MCP context overload from large tool manifests, monitoring across protocol boundaries.
  _Why interesting:_ Cleanest single-source explainer for the MCP/A2A/ACP architectural question; useful as a board-pack reference even though the closing 30% is a NeosAlpha service pitch.

- **The Narrow Waist Architecture of the Agent Transfer Protocol** — Chris Hood (en).
  Proposes AGTP as a transport-layer "narrow waist" beneath MCP/A2A, modelled on IP's design discipline. Argues that running agent protocols over HTTP forces the network to parse application payloads to make routing/governance decisions — embedding security at the application layer where prompt injection lives. AGTP moves agent identity, authority scope and audit metadata into transport headers; gateways and firewalls read the envelope, never the body. Adds cryptographic identity at the TLS 1.3 handshake (Ed25519 + X.509v3 with explicit authority-scope commitment), constant-time scope enforcement after one O(1) signature check, and AGTP-Log where the governance platform — not the agent — holds the signing key for a tamper-evident audit chain. The Agent Name Service handles dynamic discovery ranked by static trust tier + dynamic behavioural-trust score.
  _Why interesting:_ The first serious proposal this year for moving agent governance out of the application and into the network — even if AGTP itself never ships, the framing reframes the MCP-supply-chain debate as an architectural mistake rather than a procedural one.
  https://www.linkedin.com/pulse/narrow-waist-architecture-agent-transfer-protocol-chris-hood-cedec

- **Why Knowledge Graphs + RAG Is the Architecture Enterprise AI Needed All Along** — Srinivas Bommena (en).
  Long-form GraphRAG walkthrough using a pharma example ("Which drugs in Phase 3 trials for diabetes have a risk of liver toxicity?") to show how pure RAG produces fuzzy/hedged answers while a KG+RAG hybrid binds Phase-3 status, condition and adverse event in one entity-grounded answer with citations. Four-step pipeline: query decomposition → graph traversal (Cypher example for Neo4j) → targeted vector retrieval scoped to the KG-returned entities → LLM synthesis. Names three design patterns (KG-augmented RAG, RAG-augmented KG, fully-integrated graph embeddings) and positions 2026's Adaptive RAG (query-complexity router) and Agentic RAG (autonomous retrieval loops) as the next layer. Honest on cost: KG extraction still 3–5× baseline vector RAG, entity-recognition accuracy 60–85%, human-in-the-loop validation still required. Tooling map names Microsoft GraphRAG (31k+ stars), LlamaIndex KnowledgeGraphIndex, LightRAG, Cognee, Graphiti.
  _Why interesting:_ Most practical KG+RAG explainer of the week — pairs with the "2026 RAG Stack" piece from 2026-05-25 to give a complete picture of where enterprise RAG sits now.
  https://www.linkedin.com/pulse/why-knowledge-graphs-rag-architecture-enterprise-ai-needed-bommena-cl6ac

- **The Agent Harness: What It Is, Why It Matters, and What I Learned Testing OpenClaw, Hermes, and Claude** — Lionel Sim (en).
  Field report from running OpenClaw, Nous Research's Hermes Agent and Claude Code side-by-side on real workflows. Quotes the "model is commodity, harness is moat" line and cites the CORE benchmark where the same Claude scored 78% in Claude Code's harness vs 42% in a different harness. OpenClaw: best personal/community runtime (250k GitHub stars by March 2026, briefly overtaking React), strong on multi-channel persistence but heavy for narrow tasks. Hermes: built-in learning loop that autonomously creates reusable skills from successful trajectories, three-layer memory (working / episodic / skill-library), self-improvement engine gated by tests + human review — Sim is "watching this one most closely". Claude Code: production-grade harness exposed when 500k+ lines leaked via npm source map in March 2026; three-tier permission model, CLAUDE.md as version-controlled guardrails, MCP as the de-facto open standard. Closing five-point synthesis: harness > model, most agent failures are harness failures, no single best harness, Inner vs Outer Harness, MCP is the connective tissue worth investing in.
  _Why interesting:_ The most practitioner-grounded harness comparison published this week — directly applicable to choosing between Cowork-style managed harnesses and self-hosted setups.
  https://www.linkedin.com/pulse/agent-harness-what-why-matters-i-learned-testing-openclaw-lionel-sim-8pdyc
