## Pulse / long-form articles (priority layer)

**MCP in Production: Why Your AI Agents Need a Gateway Before They Hit the Real World** — Suraj Pillai (Kong), lang: en. MCP solves connectivity, not governance; walks through using an API gateway to add authn (Key Auth/OIDC), per-agent ACLs, rate limits, audit logs, and RFC 8693 token exchange for least-privilege agent-to-agent delegation. _Why interesting:_ Concrete production checklist and four MCP deployment patterns (conversion-only, listener, conversion-listener, passthrough) for an enterprise MCP control plane. [https://www.linkedin.com/pulse/mcp-production-why-your-ai-agents-need-gateway-before-suraj-pillai-j8exf]

**The Last Mile: MCP and Systems of Record in Capital Markets** — Albert Janse van Vuuren (Andile), lang: en. Maps three MCP adoption waves in capital markets (fintech rails, then data vendors like LSEG/Moody's/FactSet/Bloomberg) and the conspicuous silence from core trading platforms (Murex, Calypso, FIS, Finastra, ION) — the "last mile" through the system of record. _Why interesting:_ Grounds the identity/auditability/regulatory blockers in named vendors, regulators (FINRA, OCC/Fed/FDIC carve-out), and a maker-checker governed-agent flow. [https://www.linkedin.com/pulse/last-mile-mcp-systems-record-capital-markets-andile-ikh5f]

**What 'is' Agent Identity? Human? Workload? A new Layer?** — Christian Posta (Solo.io), lang: en. Argues agent identity is simultaneously workload identity and a layer above it; whether they collapse depends on three invariants (1:1 agent-workload mapping, a runtime registry, identity continuity across restarts). Compares kagent+Google agent substrate, AWS AgentCore, Microsoft Entra Agent ID, and Dick Hardt's AAuth. _Why interesting:_ Rare concrete treatment of agent IAM mechanics (SPIFFE, actor-class vs instance identity, intersection-of-permissions). [https://www.linkedin.com/pulse/what-agent-identity-human-workload-new-layer-christian-posta-qdamc]

**EU AI Act: High-Risk Draft Guidelines: The Key Watch Points** — Fiona Ghosh (Ashurst), lang: en. Breaks down the Commission's draft Article 6 high-risk classification guidelines: intended-purpose drives classification (disclaimers won't save you), the 6(3) filter is narrow and never applies to GDPR profiling, agentic/split architectures assessed as a single system, plus financial-services carve-outs. _Why interesting:_ Flags that modular multi-agent architecture decisions made today carry compliance consequences; consultation runs to 23 July, Annex III obligations 2 Dec 2027. [https://www.linkedin.com/pulse/eu-ai-act-high-risk-draft-guidelines-key-watch-points-fiona-ghosh-azdue]

**Is ISO 42001 Really about AI "Governance"?** — Aron Lange (GRC Lab), lang: en. Uses ISO 37000's governance-vs-management distinction to argue ISO 42001 is a management system (AIMS) with only a few governance hooks (Clause 5, framing of Clause 6); real AI governance — board owning risk appetite, independent assurance, accountability to stakeholders — sits in a layer above it that 42001 assumes but does not provide. _Why interesting:_ Clause-by-clause analysis correcting the common "42001 = our AI governance" claim. [https://www.linkedin.com/pulse/iso-42001-really-ai-governance-aron-lange-knmce]

**Why Your Private RAG is an Insider Data Leak Waiting to Happen** — Mirko Peters (m365 Show), lang: en. The "sovereignty illusion": teams obsess over data location (self-hosting, EU data centers) while permission models die in the extraction/chunking/embedding pipeline, so the vector DB has no ACLs to filter on at query time. Debunks self-hosted=secure, VPN=authorization, and "the LLM will handle it." _Why interesting:_ Actionable per-chunk metadata-filtering guidance; relevant to any enterprise RAG-on-SharePoint deployment. [https://www.linkedin.com/pulse/why-your-private-rag-insider-data-leak-waiting-happen-mirko-peters-cvwde]

**Why Claude Opus 4.8's Effort Control Changes How We Build Enterprise Finance Workflows** — Engini, lang: en. Reframes Opus 4.8's five-level effort control (low/medium/high/extra/max) as a workflow-architecture feature, not just cost optimization: assign reasoning depth per subagent role (routine matching at low effort, exception handling at max) within one governed multi-agent finance pipeline. _Why interesting:_ Pairs the model feature with non-negotiable orchestration controls (human-in-the-loop gates, immutable audit trails, connector-level scoped permissions); notes Anthropic Dynamic Workflows preview. [https://www.linkedin.com/pulse/why-claude-opus-48s-effort-control-changes-how-we-build-enterprise-ileme]

**The Harness Era: 5 Shifts That Decide Whether an AI Agent Actually Works in Finance** — Mitul Tiwari (Numos), lang: en. Five shifts for finance agents: a cross-system financial context layer as the moat; learning the "how" (behavior) over the "why" (intent); progressive disclosure / context engineering over giant context windows; "tapes" as durable audit + training assets; and separating reasoning from permission (deterministic RBAC layer the model never consults). _Why interesting:_ Concrete agent-design patterns ("Fragmentation Tax", tape-as-episode for eval/training) grounded in close/AP/AR workflows. [https://www.linkedin.com/pulse/harness-era-5-shifts-decide-whether-ai-agent-actually-mitul-tiwari-jdyff]
