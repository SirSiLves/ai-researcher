## Pulse / long-form articles (priority layer)

**MCP makes agentic AI useful. Identity attribution makes it governable.** — Steve Hutchinson (en), Jun 3 2026. Argues agentic AI breaks the human-signs-in identity model because agents act "on behalf of" people, other agents, workflows, or tool responses; proposes treating MCP servers as policy-enforcement points, audit sources, and delegation boundaries, with attributable agent identities. _Why interesting:_ A security architect's concrete operating model for agent identity/delegation — the governance layer most MCP hype skips. [https://www.linkedin.com/pulse/mcp-makes-agentic-ai-useful-identity-attribution-steve-hutchinson-bwgde]

**API Integration, A2A, and MCP: Which Protocol to Use and When?** — Sudesh Bhadouria (en), Jun 8 2026. Plain-language decision guide separating direct API integration, Agent-to-Agent (A2A), and MCP using a hospital analogy (fixed phone line vs. discoverable specialists vs. shared records), aimed at regulated-industry architects choosing between the three. _Why interesting:_ Cuts through vendor-deck confusion with a clear "which protocol when" framing grounded in banking/insurance/pharma examples. [https://www.linkedin.com/pulse/api-integration-a2a-mcp-which-protocol-use-when-sudesh-bhadouria-sv4ae]

**MCP vs. Agent Skills: Why the "Either/Or" Crowd Is Missing the Point** — Csaba Tamas (en), Jun 3 2026. Argues Skills and MCP do not compete — Skills supply reusable behaviors/prompts while MCP (now under the Linux Foundation alongside Anthropic, Block, OpenAI) supplies the standardized, governable connection layer; treating them as alternatives yields agents that are either reckless or paralyzed. _Why interesting:_ Reframes a noisy engineering debate around the real complementarity, noting MCP's Linux Foundation governance shift. [https://www.linkedin.com/pulse/mcp-vs-agent-skills-why-eitheror-crowd-missing-point-csaba-tamas-l464f]

**The Agent Capability Stack: Tool Calling, MCP, and Skills Are Layers, Not Rivals** — Giri Venkatesan (en), Jun 10 2026. Rebuts the "MCP capabilities have moved to Skills" claim (e.g. exposing the AWS CLI via a Skill instead of an MCP server); concedes the pattern is real but argues the framing is wrong — tool calling, MCP, and Skills are distinct layers an integration architect must keep separate. _Why interesting:_ An event-driven-systems advocate's layered model that pushes back on the fashionable "Skills replace MCP" take. [https://www.linkedin.com/pulse/agent-capability-stack-tool-calling-mcp-skills-layers-giri-venkatesan-helmc]

**Designing MCP Servers That Don't Become a New Mess** — William Collins (en), Jun 5 2026. Six design principles for production MCP servers — outcome-first tool design over API-wrapping, aggressive surface-area curation, bounded context resources, prompt discipline, deterministic guardrails, and production-grade failure handling, drawn from AutoCon 4 infra-ops experience. _Why interesting:_ Concrete "MCP is the standard, capability design is the differentiator" argument from someone shipping it in production. [https://www.linkedin.com/pulse/designing-mcp-servers-dont-become-new-mess-william-collins-eenge]

**Hybrid search in RAG — Why keyword + semantic retrieval works better** — Mallow Technologies (en), Jun 10 2026. Challenges the common assumption that semantic/vector search alone solves enterprise retrieval; argues that across fragmented, jargon- and ID-heavy enterprise corpora, keyword (lexical) plus semantic retrieval consistently outperforms either alone, because real environments don't behave like controlled demos. _Why interesting:_ Practical corrective to vector-search-maximalism with the enterprise-data-messiness angle. [https://www.linkedin.com/pulse/hybrid-search-rag-why-keyword-semantic-b3s0f]

**Your 40K RAG Infrastructure can be a Shared Folder** — Simon Dilhas (en), Jun 7 2026. Contrarian RAG architecture from a BIM/knowledge-management lens: most firms over-build a multi-service distributed pipeline when a shared folder plus local embeddings, chunking, a reranker, and impact analysis (open-sourced as iterthink) suffices, with a clear pain-driven scaling path. _Why interesting:_ "Start minimal, let pain drive complexity" counter to RAG over-engineering, with the local-model cost angle. [https://www.linkedin.com/pulse/your-40k-rag-infrastructure-can-shared-folder-simon-dilhas-z4hde]

**The Hidden Reason Most Enterprises Will Fail at Agentic Operations** — Mark Berly (en), Jun 4 2026. Argues the agentic enterprise is not "AI sprinkled on legacy workflows" but an environment where autonomous agents can reason, decide, and act because the infrastructure provides real-time context, constraints, and guarantees; current AI-enhanced networking falls short because it was built to generate insights for humans, not authoritative operational truth for agents. _Why interesting:_ Locates the agentic-ops failure mode in the infra/ground-truth layer rather than the model. [https://www.linkedin.com/pulse/hidden-reason-most-enterprises-fail-agentic-operations-mark-berly-vz7re]

**The EU delayed the AI Act to 2027. Your part is due in 2026.** — Sven Malvik (en), Jun 5 2026. [https://www.linkedin.com/pulse/eu-delayed-ai-act-2027-your-part-due-2026-sven-malvik--nfzne]

[https://www.linkedin.com/pulse/ai-compliance-frameworks-compared-eu-act-nist-rmf-fvsxc]
