## Pulse / long-form articles (priority layer)

**Connecting an agent is the easy part: What building a governed MCP server taught me** — Dussol (lang: en, Aug 2)
Written from a regulated financial-services seat. Part one explains MCP and the n-to-m integration mesh it replaces; part two covers the four governance questions the protocol leaves to the implementer — what an agent may ask, how often, and whether you can prove afterwards what it did.
_Why interesting:_ The only piece this week that treats MCP governance from inside a regulated bank rather than as a greenfield demo.
https://www.linkedin.com/pulse/connecting-agent-easy-part-what-building-governed-mcp-dussol-xnwse

**AI Agent Harnesses Are Becoming the Operating System for Enterprise AI** — Kevin Riedl (lang: en, Aug 2)
Argues "which model?" is the wrong opening question once agents can read documents, call APIs and modify records. The real questions — who the agent acts for, what it may access, what needs human approval, how actions are attributed and audited — are operating-model questions, not model questions.
_Why interesting:_ Frames the harness, not the model, as the enterprise control surface; uses Y Combinator's QM as the worked case.
https://www.linkedin.com/pulse/ai-agent-harnesses-becoming-operating-system-kevin-riedl--y4c5f

**The EU AI Act wants a record. Your traces are already most of one** — Jim Bennett (lang: en, Aug 4)
Responds to Angie Jones (Agentic AI Foundation) on agent record-keeping, and argues the Act's obligations largely overlap with the observability traces teams already build — a useful record must show what the agent requested and what actually happened.
_Why interesting:_ Rare compliance piece that reduces AI Act record-keeping to an engineering artifact teams already own.
https://www.linkedin.com/pulse/eu-ai-act-wants-record-your-traces-already-most-one-jim-bennett-kovpf

**From SAP Integration to Agentic AI: What I Learned Building an MCP-to-S/4HANA Bridge** — Ashutosh Moharir (lang: en, Aug 1)
Hands-on account of going from zero MCP knowledge to a working connection between an AI assistant and a live S/4HANA OData service, set against 25 years of RFC / PI-PO / BTP integration patterns.
_Why interesting:_ Concrete comparison of MCP against established enterprise middleware, plus what must be governed before production.
https://www.linkedin.com/pulse/from-sap-integration-agentic-ai-what-i-learned-building-moharir-3dd7f

**How to Build Reliable AI Agents for Production: Context, Harness, and Loop Engineering** — (lang: en, Aug 4)
Opens on LangChain moving its coding agent from outside the top 30 to the top 5 on Terminal Bench 2.0 by changing only the harness, with no model change. Attributes stalled agent projects to task design, context, permissions, evaluation and cost rather than model capability.
_Why interesting:_ Hard data point that harness engineering, not model selection, drove a large benchmark jump; cites Gartner's >40% agentic-project cancellation forecast for 2027.
https://www.linkedin.com/pulse/how-build-reliable-ai-agents-production-context-48w9e

**Your Agent Runs Other People's Code: Securing the MCP Supply Chain with Docker** — Shriram Vasudevan (lang: en, Aug 1)
Reframes an MCP server as a software supply-chain artifact: using one is not reading from an endpoint, it is granting software the right to act on the agent's behalf — touch a filesystem, call an API, move money.
_Why interesting:_ Extends twenty years of container supply-chain practice onto MCP, and separates what Docker already secures from the layer you still must check.
https://www.linkedin.com/pulse/your-agent-runs-other-peoples-code-securing-mcp-chain-shriram-pecfc

**KI-Governance und MaRisk AT 4.3.4: Was Compliance-Verantwortliche in Banken jetzt wissen müssen** — Bernhard Kessler (lang: de, Jul 29)
Argues banks waiting for dedicated AI regulation have missed that the 9th MaRisk amendment (06/2026) already embeds AI systems fully in the existing supervisory framework. Names four decisive dimensions: explainability, robustness and reliability, bias and fairness, and interpretability.
_Why interesting:_ Directly applicable to DACH/Swiss banking — the gap is enforcement of existing rules, not missing ones.
https://de.linkedin.com/pulse/ki-governance-und-marisk-434-compliance-verantwortliche-uxg6e

**We Test MCP Servers for Correctness. We Almost Never Test Them for Load.** — Shriram Vasudevan (lang: en, Aug 1)
The MCP tooling ecosystem can lint AGENTS.md, check spec conformance, audit tool surfaces for security and diff versions to catch a silent rug pull — but almost nothing answers how a server behaves under real use. Introduces a small load-testing tool.
_Why interesting:_ Names a specific, unglamorous hole in the MCP tooling stack rather than restating the protocol.
https://www.linkedin.com/pulse/we-test-mcp-servers-correctness-almost-never-them-shriram-jkmcc

**In 56 Stunden gilt die neue KI-Kennzeichnungspflicht: Was du wissen musst** — Claudia Hilker (lang: de, Jul 31)
Countdown piece to 2 August 2026, when further EU AI Act provisions — notably the Article 50 transparency duties — take effect. Sets out labelling questions for generated text, images, video and chatbots, with penalties up to EUR 15M / 3% of global turnover for operator and transparency breaches, and EUR 35M / 7% for prohibited practices.
_Why interesting:_ The Article 50 deadline passed two days ago; this is the clearest German-language operational checklist of what now binds.
https://de.linkedin.com/pulse/56-stunden-gilt-die-neue-ki-kennzeichnungspflicht-du-wissen-hilker-r3ske

**Mental Model: MCP vs. A2A explained** — Janik Emmendörfer (lang: en, Aug 1)
Rather than defining each protocol, walks a quarterly-investor-meeting scenario with a CEO agent and a CFO agent that hold role-specific tools while sharing one central MCP server for common capabilities such as email, calendar and document access.
_Why interesting:_ Shows the MCP/A2A boundary through division of labour instead of a spec comparison.
https://www.linkedin.com/pulse/mental-model-mcp-vs-a2a-explained-janik-emmend%C3%B6rfer-tpqpe

**#56 Model Context Protocol Goes Stateless: Why This Architectural Shift Changes Everything** — Imdad Areeph (lang: en, Jul 29)
The latest MCP revision removes rather than adds: it changes where conversation state lives, moving context into every request so each one is self-contained and any server instance can process it.
_Why interesting:_ Tracks a real spec-level architectural change with direct consequences for scaling and distributed deployment.
https://www.linkedin.com/pulse/model-context-protocol-goes-stateless-why-shift-changes-imdad-areeph-hx73f

**On-Premise LLM deployment and RAG: Building secure, governed, and explainable GenAI systems** — Calsoft (lang: en, Jul 30)
Positions on-prem LLM plus RAG as the practical architecture for regulated and data-intensive organisations, keeping models, prompts, embeddings and data inside a controlled environment — while insisting infrastructure alone does not deliver security or explainability.
_Why interesting:_ Matches the Swiss/regulated data-residency constraint the pipeline tracks; argues trust must be engineered across the whole lifecycle.
https://www.linkedin.com/pulse/on-premise-llm-deployment-rag-building-secure-governed-explainable-oxyqc
