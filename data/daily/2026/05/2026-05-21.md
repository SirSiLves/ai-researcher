## Research highlights

- **[A Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP](https://arxiv.org/abs/2505.02279)** — Side-by-side of the four leading agent-communication protocols with deployment-context trade-offs. The reference text when picking an agent-runtime substrate; pairs with this week's MCP-CVE discourse on the blogs side.
- **[Code as Agent Harness (arXiv 2605.18747)](https://arxiv.org/abs/2605.18747)** — Treats generated code as the orchestration substrate for LLM agents, replacing JSON tool-call plumbing with executable programs. The formal version of the "agent = model + harness" practitioner slogan.
- **[Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory (arXiv 2605.19952)](https://arxiv.org/abs/2605.19952)** — Atomic-fact memory collapses under long-horizon use; structured compositional representation preserves provenance and relational context. Direct relevance to the Dreaming / persistent-memory push at Code with Claude.
- **[Predictive Maps of Multi-Agent Reasoning: A Successor-Representation Spectrum (arXiv 2605.11453)](https://arxiv.org/abs/2605.11453)** — Borrows the successor representation from RL to predict ahead of time which communication topology a multi-agent LLM team should adopt — no post-hoc topology sweeps.
- **[Beyond Accuracy: Policy Invariance as a Reliability Test for LLM Safety Judges (arXiv 2605.06161)](https://arxiv.org/abs/2605.06161)** — Reliability of LLM-as-judge for safety is mis-measured by accuracy alone; introduces a policy-invariance test that flags judges whose verdicts swing under benign policy rephrasings.
- **[MARLIN: Multi-Agent Game-Theoretic RL for Sustainable LLM Inference in Cloud Datacenters (arXiv 2605.13496)](https://arxiv.org/abs/2605.13496)** — Co-optimizes latency, cost, and carbon for LLM serving — for platform/operations teams sizing inference fleets.
- **[AJAR: Adaptive Jailbreak Architecture for Red-teaming (arXiv 2601.10971)](https://arxiv.org/abs/2601.10971)** — Holistic red-teaming framework that targets LLM-based **agents** (persistent state, tool access, autonomous loops) — most current jailbreak benchmarks don't reach this surface.
- **[Benchmarking Filtered Approximate Nearest Neighbor Search on Transformer Embeddings (arXiv 2507.21989)](https://arxiv.org/abs/2507.21989)** — New 2.7M-paper benchmark (`arxiv-for-fanns`) covering eleven FANNS methods. Concrete baseline for vector-DB selection — useful evidence base now that Pinecone is repositioning the whole category.
