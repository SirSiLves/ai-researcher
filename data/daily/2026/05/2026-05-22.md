## Research highlights

- **MCJudgeBench — Constraint-Level Judge Evaluation in Multi-Constraint Instruction Following** ([arXiv 2605.03858](https://arxiv.org/abs/2605.03858)) — Pushes LLM-as-judge from "did it follow the instruction" to per-constraint verdicts. Exposes that judges are weakest exactly where production prompts live.
- **Towards Reliable LLM Evaluation: Correcting the Winner's Curse in Adaptive Benchmarking** ([arXiv 2605.05973](https://arxiv.org/abs/2605.05973)) — Adaptive prompt/program search inflates reported scores via winner's-curse effect; proposes correction so leaderboards track fresh-data performance.
- **Towards Dependable RAG Using Factual Confidence Prediction** ([arXiv 2605.05244](https://arxiv.org/abs/2605.05244)) — Trains confidence predictor over RAG outputs so the system can abstain or escalate when factual grounding is weak — deployable primitive for high-stakes RAG.
- **MCP Tool Descriptions Are Smelly! Augmented MCP Tool Descriptions** ([arXiv 2602.14878](https://arxiv.org/abs/2602.14878)) — Empirical study showing real-world MCP tool descriptions exhibit code-smell-like quality problems that hurt agent tool selection; augmentation heuristics lift downstream task success.
- **Enhanced LLM Reasoning by Optimizing Reward Functions with Search-Driven RL** ([arXiv 2605.02073](https://arxiv.org/abs/2605.02073)) — Search-driven RL over the reward function itself (not just the policy) closes a gap where RLHF reward shaping is hand-tuned.
- **EngiAI — Multi-Agent Framework + Benchmark Suite for LLM-Driven Engineering Design** ([arXiv 2605.19743](https://arxiv.org/abs/2605.19743)) — Standardizes evaluation across decomposition, constraint checking, artifact generation; pushes agents beyond chat/code into engineering workflows.
- **MARLIN — Multi-Agent Game-Theoretic RL for Sustainable LLM Inference in Cloud Datacenters** ([arXiv 2605.13496](https://arxiv.org/abs/2605.13496)) — Multi-agent RL co-optimizing latency, cost, carbon for LLM serving; relevant for platform/operations teams defending cost-per-token economics.
- **Towards the Next Frontier of LLMs, Training on Private Data — Federated Fine-Tuning Cross-Domain Benchmark** ([arXiv 2605.13936](https://arxiv.org/abs/2605.13936)) — Healthcare/finance benchmark for federated fine-tuning; concrete reference for enterprises that can't ship data to a central trainer.
