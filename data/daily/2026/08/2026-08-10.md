## Research highlights

_arXiv announced a **Mon, 10 Aug 2026** batch — cs.CL IDs `2608.064xx`–`2608.074xx`, cs.IR `2608.066xx`–`2608.071xx`. This is a genuine Monday artefact: the 08-11 papers collector's morning pass ran before the Tuesday announcement and therefore covered the Monday batch exclusively, so everything below carries a 10 Aug announcement date. Confidence here is the highest in the file._

**[DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds](https://arxiv.org/abs/2608.06113)** (2608.06113, cs.SE — Waterloo) — See Top-5. Planning structure is currently a scaffold artifact and needs to become a learned model capability.

**[The Horizon Gap: Planning, Memory, Execution, Training, and Evaluation for Long-Horizon LLM Agents](https://arxiv.org/abs/2608.06663)** (2608.06663, cs.CL) — Surveys 1,547 papers (2024–2026) and does the disambiguation the field keeps fudging: long-horizon (task property) vs. long-context (model property) vs. long-term memory (system property). One pattern everywhere — outcome-only signals go uninformative as horizons lengthen, and every fix is really manufacturing denser step-level signal. Closes on the commercially decisive measurement problem: you cannot currently separate model capability from harness capability. Dovetails exactly with DCAS, announced the same day.

**[CoinRAG: Contextualized Information Nugget KV Cache Reuse for Long-Context RAG](https://arxiv.org/abs/2608.07458)** (2608.07458, cs.CL/cs.AI/cs.IR/cs.LG) — Goes finer-grained than chunk-level KV cache reuse: two-stage retrieval picks query-relevant semantic units *inside* each chunk and assembles their sliced KV representations, cutting prefill cost while gaining 5.3% relative F1 on LongBench multi-hop QA. The prefill-cost lever that decides whether long-context RAG is affordable in production.

**[LLMRouter: Unified Infrastructure for Developing, Evaluating, and Deploying LLM Routers](https://arxiv.org/abs/2608.06867)** (2608.06867, cs.CL) — One framework covering the whole router lifecycle — train, benchmark, serve — rather than another one-off routing heuristic.

**[From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL](https://arxiv.org/abs/2608.07213)** (2608.07213, cs.CL — Xidian / SJTU) — Asks whether expensive test-time search can be "crystallized" into reusable memory so the second run is cheap. The economic question behind every agent-memory product, measured on a concrete task with reproduction artifacts released.

**[Zero Gap Is Not Restoration: Stratified Per-Question Probability Evaluation of Benchmark Contamination](https://arxiv.org/abs/2608.07341)** (2608.07341, Zhejiang) — Closing the contamination gap on aggregate is not the same as restoring an uncontaminated benchmark; gives a per-question stratified probability test instead. Direct ammunition when a vendor waves a benchmark score.

**[Exact Adaptive Hybrid Retrieval Without Fixed Top-L Cutoffs](https://arxiv.org/abs/2608.07152)** (2608.07152, cs.IR) — Drops the arbitrary top-L truncation in hybrid sparse+dense retrieval while keeping exactness, removing a tuning knob that quietly caps recall in most production RAG stacks.

**[Skaling: Chinchilla's Exponents Meet Kaplan's Coupling](https://arxiv.org/abs/2608.07222)** (2608.07222, AI at Meta) — Reconciles the two canonical scaling-law families that have disagreed for four years. Note the same-day symmetry: Meta shipped Muse Glimmer and a scaling-law reconciliation on one Monday.

**[DocMemo: Dynamic Evidence Discovery via Probabilistic Memory-Guided Retrieval for Multi-Modal Document Understanding](https://arxiv.org/abs/2608.07067)** (2608.07067) — Tri-level memory plus dynamic Bayesian belief updating replaces static top-K retrieval for long-document reasoning, so evidence is tracked across the document rather than re-fetched blind at each step.

**[The Optimizer Is the Agent: Reasoning-Driven Search across Prompts, Programs, and ML Workflows](https://arxiv.org/abs/2608.06714)** (2608.06714) — Unifies prompt optimization, program synthesis and ML-workflow tuning as one reasoning-driven agentic search problem rather than three toolchains — the natural generalization of DSPy-style optimizers.

**[An Agentic Hybrid Top-Down and Bottom-Up Approach to Knowledge Graph Generation](https://arxiv.org/abs/2608.07023)** (2608.07023) — Uses an agent to reconcile schema-first and data-first KG construction in one loop; the practical path for enterprises that have an ontology on paper and messy documents in reality.
